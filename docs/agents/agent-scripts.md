# Agent scripts

Run from the worktree root; dependencies must already be installed.
The order runners use these in: [runner.md](runner.md).

Agent tool hooks and session Node PATH: see [Hooks](guardrails.md#hooks).

## Kit

`scripts/agents/kit <command> [args]` is the front door. Bare `kit` lists the commands;
`kit <command> --help` prints that command's usage and is the source of truth for its flags.
Every run ends with one `RESULT: ok|fail …` line (the kit adds one when a command does not, or
is interrupted); exit 0 ok, 1 failure, 2 usage error. `kit review` may also end
`RESULT: skip review out of credit (<model>)`, or with `--second-look` `RESULT: skip second look (<reason>)`, with exit 3. Each command is one file with a
`# kit: <summary>` line and its own `tests/kit-<command>.test.ts`: shared commands in
`scripts/agents/kit.d/`, the project's own in the folder `commands` names in the settings file
(here `scripts/agents/project.d/`: `specs`, `shots`, `size`, `preview`; their helpers stay in
`scripts/agents/`). Bare `kit` lists the two groups apart. A project command may not take a shared
name: the shared one runs and `kit doctor` fails naming both files. `KIT_COMMANDS_DIR` (tests)
replaces both folders. Shared helpers live in `kit-lib.sh` and `kit-lib.mjs`. Owner: `ASE_OWNER`,
else `.scratch/owner`.

Project values come from one settings file, `scripts/agents/kit.json`, read from the project's top
folder (`git rev-parse --show-toplevel`, or `KIT_ROOT`), so each worktree reads its own checkout's
copy: `kitSettings()` in `kit-lib.mjs`, `kit_setting <jq path>` in `kit-lib.sh`. Only `project` and
`branches.land` are required; `kit doctor` fails with what to add when the file is missing, broken or
lacks them. The other keys are optional and a missing one turns its feature off with a plain line:
`commands` (the project's own commands folder, relative to the top folder or absolute; without it
only shared commands; `kit pr` runs `kit specs` only when it holds a `specs` command), `mainRoot`
(else the main worktree), `allowMainCheckout` (`true`: `kit doctor` accepts the main checkout, for a
project worked on there), `devRoot` (`next` and `heartbeat` say they need one; `worktrees.sh` never prunes it),
`worktreePrefix`, `sharedNodeModules` (without it `kit doctor` skips the `node_modules` check and
`kit pr` skips `kit deps check`), `branches.release` and `branches.ci` (else `land`; a `release`
equal to `land` takes ordinary PRs), `checks` (`check`, `test`, `lint`: any command, for example
`python3 .checks/site.py`, run by `kit pr` and named by the review, slice and fix briefs, a missing one is
skipped; `css`, the colour check `kit pr`'s css tier runs; `extra`, one command or a list of kit-plumbing
checks run only when a `paths.kit` file changes (anything else fails `kit pr` with
`checks.extra must be a list of commands`); `doctor`, one command or a
list, each an extra `kit doctor` line that passes on exit 0), `unit` (`run`, a Node test-runner
command such as `node --test`, to which `unit.sh` adds `--test-timeout` and the files; `files`, one
pattern or a list, each a glob where `*` stays in a folder and `**` spans folders, or a folder ending
in `/` for the `.js`, `.mjs` and `.cjs` files under it, as `node --test` runs a test folder (TypeScript
tests there need a glob such as `test/**/*.test.ts`), matched against git's tracked and
untracked, not-ignored files by `kit unit` (`unit.sh` with no files runs what `kit unit --list`
lists); the slice and fix briefs name `kit unit --affected` only when it is set;
`docsGuards`); `checks` commands and `unit.run` are split on
spaces, with no quoting, `paths` (`docs`, `tests`, `css`, `visible` regular expressions for `kit pr`'s tiers
and feature-list guard; `kit`, the kit-plumbing files that run `checks.extra`; `unitTests`, the unit test
files `kit pr` picks its focused run from), `featureList`, `techDebt`, `standards` (one file or a list, such as
`["AGENTS.md"]` where a project has none, for the review brief), `maps`, `sharedFile`, `preview`
(`status` skips the preview row without it), `playwright` (where Playwright comes from for a project
without its own: a module file or folder, relative or absolute, that `kit doctor` checks and project
commands read), `servers` (the command `bash-guard` names for starting servers; else
`scripts/agents/port.sh` where the project has one, else `kit bg`) and `rulebookExtras`. A project
with no `origin` remote (git's "No such remote") has no GitHub repo: `kit pr` stops with `no GitHub repo`, and `kit wait ci`,
`kit status` and `kit doctor` say so and carry on. Environment
overrides keep winning over the file: `KIT_MAIN_ROOT`, `KIT_DEV_ROOT`, `KIT_PREVIEW_URL`, `KIT_PLAYWRIGHT_MODULE`. This
editor's file holds Lex's machine folders (`/home/ubulex/...`); on another machine set those
overrides or edit the file.

One kit for the whole machine (ticket 30 moves this editor onto it; until then `scripts/agents/kit`
here is still the full front door). Clean, read-only kits sit in
`${XDG_DATA_HOME:-~/.local/share}/agent-kit/<commit>/` with a `current` link to the newest, filled by
`kit update`. `kit init` (ticket 22, not built yet) will write two templates from `scripts/agents/launcher/`
into a project: `kit` becomes its `scripts/agents/kit` and `hooks-run.sh` its `scripts/agents/hooks/run.sh`. The launcher
reads `current` once and sets `KIT_HOME` to that exact folder for the whole command, so a long slice
keeps one kit while an update lands; a `KIT_HOME` a person set wins (trying a kit branch). Beside the folder it
picks it exports `KIT_HOME_PINNED`, so a child (a builder session, a `kit bg` job) whose inherited folder `kit update`
has since removed picks again from `current` or the cache clone, while a person's `KIT_HOME` that holds no kit
still fails (and theirs wins over a different `KIT_HOME_PINNED`). Both launchers take only a whole kit, as
`kit update` checks it (`kit` executable and `kit-lib.sh`); the hook launcher also needs `hooks/run.sh`, so a
pinned folder without it is kept for commands while hooks look up `current` or the cache clone again. A folder
the kit launcher picked that is removed while it starts ends `(removed while starting)`, naming the folder. With no
machine copy (GitHub Actions, a cloud session, a new laptop) it clones the newest kit `--depth 1` into
`${XDG_CACHE_HOME:-~/.cache}/agent-kit`, outside every project, and reuses that clone (never refreshed in
place; `kit version` and `kit doctor` warn once it is a day old, and `kit update` then fills the machine copy; a
cache folder that is not a whole kit ends `<folder> exists but holds no kit; remove it`, a fresh clone that is
not one `the clone of <repo> holds no whole kit`, a whole clone whose time stamp cannot be written
`cannot stamp the clone in <cache>`, and one that cannot be moved over a folder that is not a kit
`cannot place the clone at <folder>`; one that loses the move to another launcher's whole clone uses that). `KIT_REPO`
is the kit repo, a setting at the top of the launcher. The hook launcher finds the kit the same way
(without cloning) and runs the kit's own `hooks/run.sh`, never the front door, so no `RESULT:` line
reaches session context. Without a kit it never blocks and never goes quiet: it prints
``Agent Kit not found: guards are off; run `scripts/agents/kit doctor` `` as SessionStart context and
as a `systemMessage` on every guarded call.

- `kit update [--previous]` fetches the kit repo's `main` (`KIT_REPO`, shallow, into the copy's
  `repo.git`), unpacks the newest commit into a new read-only folder and swaps `current` in one rename;
  folders that stopped being current over a day ago go, never the current or previous kit.
  `--previous` points `current` back at the kit it replaced, for every project at once (the
  emergency switch), and later updates stay there until `main` moves on; the normal way back is a
  revert in the kit repo. It refuses a previous folder without `kit` and `kit-lib.sh`
  (`update previous kit <commit> is incomplete`, `current` unchanged), and a second `--previous` changes
  nothing (`update already back on <commit>`). Updates take turns under `flock`; without it `kit update` says
  `no flock; updates are not serialised` and carries on. A removed or broken current folder is
  unpacked again even when `main` has not moved (`update refilled <commit>`); while held, that is the
  kit `--previous` went back to, and `held` stays (`update cannot refill held <commit>` when
  `repo.git` no longer has it, and nothing moves).
- `kit doctor [--quiet]` checks the settings file, place, base, hook config, live hooks, Node, `node_modules`, conflict markers, that no project command takes a shared name (and that the `commands` folder exists), and that every kit command in both folders answers `--help` (exit 0 with a `Usage:` line within `KIT_HELP_TIMEOUT` seconds, default 10; the helps run side by side and each broken command is named with its exit, `no usage` or `timed out`), each ✗ with a fix, then one line per `checks.doctor` command and a `playwright` line when that setting is set; the RESULT counts every line it checked (`11/11` here). Without `--quiet` it also notes whether the optional `grok` reviewer is installed and logged in (✓/✗ from `grok models`: logged in, not logged in, timed out, failed or unrecognised output; never a failure; `KIT_GROK` names another binary and `KIT_GROK_TIMEOUT` its timeout in seconds, default 10, for tests). It first fetches the land branch (`KIT_DOCTOR_FETCH_TIMEOUT` seconds, default 20; a failed fetch is noted on the base line and the last fetched tip judged). The base passes when the branch contains `origin/<land>` (`origin/dev` here), when the main checkout of an `allowMainCheckout` project is on the land branch, or its base was the land tip less than 24 hours ago ("N commits behind; rebase before landing"; `kit pr` rebases). `agent.sh` runs `--quiet` on its worktree and exits 3 on failure. With `KIT_DOCTOR_SKIP=help` (set by `agent.sh` for builds; doctor honours no other name) a broken help prints `problem: help: …` instead of failing, is left out of the count, and the RESULT ends `; skipped help (KIT_DOCTOR_SKIP)`. A failing `kit home` check (which runs `kit version` in a copy within `KIT_HOME_TIMEOUT` seconds, default 10) does the same (`problem: kit home: …`; `skipped help, kit home`) only when the copy fails as `version`'s help did: both time out, or both exit with the same status and print the same lines in the same order (the copy's path read as the kit's, the front door's own RESULT line left out; the front door relays only stdout, so a `version` writing to both streams may come out reordered and keep the gate); any other failure, such as a missing helper or a kit home that cannot be copied, still fails. The `hooks live` probe runs as a hook starts, without the command's `KIT_HOME`; a hook launcher that finds no kit fails it as `hooks cannot reach a kit`. A `kit` note, never counted, shows the kit's commit and age beside the project's commit (from `kit version`, within `KIT_HOME_TIMEOUT`); a machine copy over a day without `kit update`, or a launcher cache clone over a day old, turns it into a ✗ warning, shown even with `--quiet`, and the RESULT ends `; warning: kit not updated for N days` (a machine copy with no update time: `; warning: kit update time unknown`).
- `kit review [--base REF | --commit SHA] [--ticket FILE] [--pr N] [--second-look]` runs one read-only review (default `--base origin/dev`; model `ASE_REVIEW_MODEL`, else `claude-opus-5-5`: `claude-*` runs Claude, `grok-*` (e.g. `grok-4.7`) runs the `grok` CLI headless in its `read-only` sandbox with only read/grep/list tools, `opencode/<model>` (e.g. `opencode/deepseek-v4.1-flash-free`) runs `opencode run` as an agent allowed only read/grep/glob/list, anything else runs Codex; Codex gets a fresh `CODEX_HOME` with no skills, plugins or MCP servers). Outside families have weekly budgets, counted per UTC ISO week for the whole computer in the kit's state folder (`$XDG_STATE_HOME/agent-kit`, else `~/.local/state/agent-kit`; `kitStateDir` / `kit_state_dir`) `review-budget.json`, by project (`project` in `scripts/agents/kit.json`), keeping this week and last; the first GPT or Grok review (even one refused at the limit) moves a project's old main root `.scratch/review-budget.json` in once and removes it (a broken old file stops the review and is kept; a held lock on it skips the move until the next review; a failed ledger write puts the counts back): `gpt` (Codex) `ASE_REVIEW_BUDGET_GPT=12`, `grok` `ASE_REVIEW_BUDGET_GROK=8`. It prints `budget: <family> <used>/<limit> in <week>`, waits up to `ASE_REVIEW_BUDGET_LOCK_MS` (10000) for the ledger lock, refuses at the limit (`problem: <family> review budget used up …; raise ASE_REVIEW_BUDGET_<FAMILY> to override`) and gives the reservation back when the CLI never started (empty diff or missing CLI) or when the provider refused the first call outright with a usage-limit message; any other started review counts even if it fails, times out or is refused on its completeness retry. Claude and OpenCode (free models) are never counted. Only `kit review` counts: `review.sh` and a direct `agent.sh review` skip the ledger. A provider usage-limit message ("You've hit your usage limit … try again at <time>") becomes `problem: <family> usage limit until <time>` when it is one of the CLI's last output lines; an OpenCode error event with HTTP 429 or a rate, usage, quota or insufficient-credit message becomes `problem: opencode usage limit: <message>`, whatever its exit status. An empty account is its own result: a Grok closing line or JSON error event (`{"type":"error"}` on stdout, whose wrapped API error has `http_status` 402), or an OpenCode error event or closing line, with HTTP 402, "Payment Required" or "balance exhausted" becomes `problem: <grok|opencode> out of credit: <message>` as the last problem line (only the CLI's own closing lines that start with the 402 or its message count, so a review or tool trace naming "402" is not matched); a failed run that ends so prints `evidence: <path>` then `RESULT: skip review out of credit (<model>)`, exits 3 and gives its weekly count back, even after earlier turns and even when saving its evidence then fails (that run ends `RESULT: fail saving evidence failed …`, exit 1); when giving the count back fails, the skip line ends `; count not given back`. When an OpenCode call exits non-zero after an error event that is not a limit, the last problem line is `problem: OpenCode reported an error: <message>`. Exit codes: 0 reviewed, 1 failed (including a usage limit), 2 invalid arguments, 3 skipped out of credit. It saves `result.md`, `run.log`, `diff.patch`, `refs.txt` and `findings.json` in the main root `.scratch/reviews/<owner>/<UTC time>/`, named in the RESULT line, and prints a `findings N: <kind counts>; <severity counts>` line. Its temporary review folder is removed only after every copy and `findings.json` are saved; when saving fails it is kept and named (`problem: review files kept in <path>`); when only its removal fails, the review keeps its result and prints `problem: removing <path> failed: …`. `findings.json` is `{ model, effort, scope, head, findings: [{ group, severity, kind, text }], counts: { kind, severity } }` (validation gaps count as `gap` in both; severity `none` is a defect whose severity could not be read), or `{ model, effort, scope, head, unreadable: true }` when the report does not parse; `kit fix` appends `declined: [{ text, reason, round }]` from the builder's `Declined:` list (`- <finding> — reason: <why>`; an item without `— reason:` keeps its whole text and an empty reason); a retried round replaces its own entries. An empty diff fails before the model; an incomplete answer is re-asked once. Defects use `commit:path:line — P0/P1/P2/P3 <kind>: evidence and fix`, where kind is `fault` (the code is wrong), `ticket` (mismatch with the ticket or spec), `race` (timing, ordering or stale state) or `style` (standards or readability, no behaviour change); a missing or unknown kind is `unsorted` and blocks only by severity. P0 means data loss, security holes, broken build/tests or a wholly broken change; P1 means wrong user/runner behaviour or a broken ticket "Done when" item; P2 means a minor real defect; P3 means cosmetic/style. Validation gaps have no severity. `--second-look` is the second look after Claude's review ([pins](kitchen.md#who-cooks-pins-from-2026-10-22)): the changed paths, leaving out ticket files (the `--ticket` one and any `tickets/<name>.md`) and the `featureList` file unless nothing else changed, give the review kind, the first any path reaches of `agent` (`paths.agent`, default `scripts/agents/`, `.claude/`, `.codex/`, `AGENTS.md`, `CLAUDE.md`, `docs/agents/`, plus `paths.kit`), `ux` (`paths.visible`), `dx` (`paths.dx`, default `scripts/`, `.github/`, `package.json`, `tsconfig*.json`, `*.config.{js,ts,mjs,cjs,mts,cts}`, `wrangler.json(c)`, plus `paths.docs`), else `code`, and it prints `second look: <kind> (<deciding path>) <model>`. The kind's row in [`scripts/agents/second-look.json`](../../scripts/agents/second-look.json) (`ASE_SECOND_LOOK` names another table, for tests) gives the model and the other family's fallback, each `grok-<model>` or `opencode/<model>` (a table with any other model, or one family twice, fails); `ASE_REVIEW_MODEL` and `ASE_AGENT_CLI` cannot redirect it, so it never reaches Codex. When the model cannot run (its weekly count used up, out of credit, a usage limit, a missing CLI (`CLI missing: spawn <cli> ENOENT`), OpenCode's `OpenCode reported an error: …` or no session within its start limit (`opencode unavailable: no session within <s>s`), a Grok run whose last five lines include one starting with an HTTP 5xx or a connection error (`grok unavailable: <line>`; its weekly count is given back, as for an empty account), or a Grok run with no answer before the review timeout (`grok unavailable: no answer within <limit>`; Grok prints its answer only at the end)) it prints that run's `evidence:` and `second look: <fallback> takes it (<model> <reason>)`; any other failure (one before the CLI starts, an incomplete answer, an OpenCode timeout after its session started, a failed save or PR comment) ends `RESULT: fail …`, exit 1, with no handover. When the fallback cannot run either it prints `second look: skipped (<model> <reason>; <fallback> <reason>)` and `RESULT: skip second look (…)`, exit 3. A bad scope, an empty diff or a broken table fails as usual (exit 1). Each run's evidence folder gets `second-look.json` (`{ kind, model, ok }`) as soon as it is made, before any review file is copied in, and `ok` turns true only for a run that came back, so the slice's and `kit pr`'s lookups never take it for Claude's review and reuse only a second look that ran; with `--pr` its comment starts `Second look: <kind>`.
- `kit heartbeat <map> [--start]` is the lead's 30-minute build check-in ([kitchen.md station 5](kitchen.md#5-hand-out)). From every worktree's `kit bg --list` it takes the `slice-*` jobs with a recorded `--ticket` in `docs/wayfinder/<map>/` (a group job from `kit next --run-group` has one per ticket: its lines read `<job> tickets=<a>,<b>`, its logs are every ticket's slice folder, and each slice merged before it ended gets a `merged:` line) and prints `finished: <job> <exit> <last RESULT:>` once per job run (reported runs and log sizes in the main root `.scratch/heartbeat/<map>.json`; a rerun under the same name is new; one heartbeat per map at a time under `flock`, a second waits up to `KIT_HEARTBEAT_LOCK_WAIT` seconds, default 600), `merged: <job> PR #N <sha>` plus one `preview:` reminder for the lead's `kit preview` (it never deploys), `running: <job> age <t> log +<growth>`, `stuck: <job> log quiet <t>` when nothing was written for 45 minutes (logs are the job log plus the slice's `.scratch/kit-slice/<ticket-slug>/` files two levels deep: phase logs and `builder/run.log`; the job log alone gets one line per finished phase), then `kit next <map>` (with `--start` when given; stderr kept in order; killed after `KIT_HEARTBEAT_NEXT_TIMEOUT` seconds, default 1200, as `next timed out after <n>s`; its `running:` lines are dropped and its RESULT is printed as `next RESULT: …`), then two plain lines for Lex, `done: …` and `running/next: …`. Last line `RESULT: ok heartbeat continue`, or `RESULT: ok heartbeat stop (frontier empty)` / `stop (only Lex-waits left)` when nothing runs, starts or is ready and every `waits:` line is `needs Lex` or `build not started`; a `claimed by …, no running job found` wait (a failed slice the lead reruns, or a delegated ticket the free worker builds) keeps it going and is named in `running/next:` as `claimed with no job (<ticket>); the lead looks at it`, and Lex-waits as `<n> waiting on you (<ticket>; …)`; a group's `waits: group <slug> tickets=<a>,<b> <reason>` line counts as one item, `group <slug>: <a>, <b>`. A job listed `died` without a `pid` record in its first minute (or before its start time is written) is still launching and counts as running; a failed `kit next` ends `RESULT: fail heartbeat next …`; any other failure (lock timeout, `git worktree list`, `kit bg --list`, a `kit next` timeout, the locked run killed by a signal) still prints `done: unknown (heartbeat failed)` and `running/next: the heartbeat failed (<why>); the lead looks at it` before `RESULT: fail heartbeat …`.
- `kit next [map…] [--start] [--max N]` hands out work by fixed rules: it reads the open frontier from `origin/dev` in the dev worktree (`KIT_DEV_ROOT`) and every worktree's running `slice-*` jobs (`kit bg --list`; each job's recorded `--ticket` gives its Files), then prints `running: <job> <ticket>`, `next: <ticket> builder=<model> owner=<owner> why=<slot>` and `waits: <ticket> <reason>` lines and `RESULT: ok next <n> ready, <m> waiting`. Rules, in order: only unclaimed `type: task (AFK)` tickets (a claimed one with no running slice prints `waits: … claimed by <owner>, no running job found`: a failed start or a delegated ticket), none from a map whose build README has a `**Not started:**` line above its first `##` heading; at most 5 running slices (`--max` lowers it; delegated picks take no slot); at most 2 in `src/main.ts`; no file shared with a running or newly picked slice (exact paths, dot folders such as `.github/` included; a plain word without backticks needs a path shape, so "and/or" is prose; a glob, placeholder or "find it with" line counts as its directory; `src/main.ts` is left to the previous rule); `runs_alone: true` waits for every other slice of its map and blocks new ones while it runs. Maps go in the order given, else alphabetical; tickets by number. Any malformed ticket in the loaded maps (all maps when none is named) stops the hand-out with `RESULT: fail next <n> ticket problems`; a job name `kit bg` would refuse waits for a `prefix:` line. Builders follow the [pins](kitchen.md#who-cooks-pins-from-2026-10-22): `claude`, `sol` or none → `claude-opus-5-5`, `opencode/<model>` → `delegate opencode/<model>` (T3 `delegate_task`), anything else as written. Owners are `<prefix>-<NN>` (the build README's `prefix:` line, else the map name; `<prefix>-m<NN>` for the map's own `tickets/`, which are numbered apart), and a job name already running or picked in the same run waits. `--start` claims each `next:` ticket on `dev` from the dev worktree (refuses unless it is on `dev`, clean and not ahead; fast-forwards, rechecks the ticket, fills `assignee:`, commits `docs: claim <map> <NN>`, pushes, and on a rejected push rebases and retries once; any failure before the push lands resets `dev` to `origin/dev`), then makes `build/<owner>-<slug>` with `worktree.sh` and starts `ASE_REVIEW_MODEL=claude-opus-5-5 kit bg slice-<prefix><NN> -- scripts/agents/kit slice --ticket … --builder <model>` there, printing its `wait: KIT_ROOT=<worktree> scripts/agents/kit wait job …` line; delegated tickets are only claimed (`delegate:` line). A start that fails after its claim landed ends `RESULT: fail next start <ticket>: claimed <sha> but not started: …`. Tickets of one map with the same `group:` are one hand-out: it waits (`waits: group <slug> tickets=… waits for <NN-slug> (blocked)`) until every member not closed or `wontfix` is open and blocked only by closed tickets or by members, then prints one `next: group <slug> tickets=<a,b,c> builder=… owner=<prefix>-g-<slug> why=…` line with the tickets in `blocked_by` order; it counts once toward the cap, the union of its Files meets the `src/main.ts` and shared-file rules, and members needing Lex, differing builders, a partial claim or a `blocked_by` cycle make it wait. `--start` claims all its tickets in one commit (`docs: claim <map> group <slug>`), makes `build/<prefix>-g-<slug>` and starts one `kit bg slice-<prefix>g-<slug> -- scripts/agents/kit next --run-group --branch build/<prefix>-g-<slug> --builder <model> --ticket … --ticket …` job, which runs `kit slice` for each ticket in order in that worktree (one model, a fresh builder session per slice) and stops at the first failure or a dirty worktree; the first slice runs on `--branch`, each later one on a new branch `<branch>-<NN>` (`m<NN>` for a map ticket) from the fetched `origin/dev`, as `kit pr` rebase-merges and deletes the last one. To resume a stopped group, rerun the job's command (`kit bg` with the same name and command): it skips tickets closed on `origin/dev` or merged by their saved slice (`.scratch/kit-slice/<slug>/state.json` with `pr` finished) and returns a slice with saved state to its branch. Before claiming, a group is rechecked on the fast-forwarded dev: a member claimed meanwhile, joining or leaving, newly blocked, or with a changed builder or type leaves the group unclaimed, and a lone ticket that gained `group:` meanwhile is not claimed alone (`claimed meanwhile (group changed)`).
- `kit slice --ticket FILE --builder MODEL [--effort high] [--rounds 3] [--no-pr]` writes the brief, builds (`sol` = `gpt-6.1-sol`), commits through normal Git hooks, reviews, fixes up to three rounds and lands via `kit pr`; start under `kit bg` and wait once. Reruns resume saved phases in `.scratch/kit-slice/<ticket-slug>/`, re-reviewing moved HEADs unless only the ticket changed since the covering review; a rerun may name another `--builder` or `--effort`, keeping finished phases, recording the old model in `previousModels` (or effort in `previousEfforts`), printing `builder switched: <old> -> <new>` and passing the new model and effort to later fix rounds (a fix round paused in its commit or review step first finishes under its saved model), while a different ticket or branch still refuses. Failures show at most 15 log lines. Every finding blocks before three completed fix rounds; afterwards only P0/P1 defects, defects without readable severity and unreadable reviews block, while P2/P3 defects and validation gaps proceed to `kit pr` as follow-ups. Then the UX gate: `kit ux --ticket <t>`; nothing visible touched prints `slice: ux ok skipped: nothing visible touched`. A broken or looks off feature gets one `kit fix --note <bundle>/ux.md` round (it counts as a fix round and is reviewed again; open blocking findings after it stop the slice), then `kit ux` again: still broken stops with `decide: ux broken <feature,…>`, looks off proceeds and its lines go under `### UX follow-ups` in the ticket's last `## Done` section (made when missing), one per feature (a feature already listed keeps its line), images named from the main root, the report saved first so a rerun after that commit reuses it, in one ticket-only commit (`docs: <slug> UX follow-ups`) made only on the HEAD the check saw with a clean tree. The UX round's own review gets the usual fix rounds (a half-done one resumes first); blocking findings left after them stop the slice. A `kit ux` failure with no report (failed or unreadable reviewer, even beside a failed try) or one that breaks no feature (failed screens run) stops the slice without a fix round. A rerun checks again without a second UX fix round. `--no-pr` stops after the review/fix and UX gates; the slice never passes `--waive`. Fresh slices require a clean worktree; existing slices may resume pending changes. A queued slice refuses `--no-pr` if local HEAD moved. Queued PRs are saved and awaited until merged (two-hour timeout; retries resume the wait); unexpected PR failures keep their bounded PR log digest. - `scripts/agents/cold.sh <worktree> <outprefix>` serves existing `dist` on `5216`, records the served index asset, measures five cold/warm runs with `ASE_COLD_NET=100/20`, waterfall and JSON; run through `timing.sh`.
- `scripts/agents/full-suite.sh [shards=3]` runs native-save shards in parallel with one worker each, separate artifacts, line logs and JSON; caps shards to currently free slots (at least one), prints the count, waits, summarizes, and fails if any shard fails. Each shard acquires any eligible slot through `port.sh`. `ASE_SHARDS` sets the default. Allow 25–50 minutes with 3 shards on a busy machine.
- `scripts/agents/reap.sh [--dry-run]` kills orphan test servers on unlocked slots; `--dry-run` lists them.
- `scripts/agents/worktree.sh <branch> [base=origin/dev]` creates a sibling worktree with shared dev `node_modules` and native-static fixture symlinks; records UTC time, `${ASE_OWNER:-unknown}`, branch and base in `.scratch/owner`, then prints its path. Set `ASE_OWNER` to the agent/thread identifier.
- `scripts/agents/worktrees.sh [--prune] [--older-than DAYS=3]` lists registered paths, branches, owners, dirtiness, commit age, merge state against the local `origin/<land>` or `origin/<release>` (`origin/dev` or `origin/main` here), and live cwd state from `/proc`. Listing is the default. Prune removes only clean, merged, inactive worktrees whose commit and creation ages exceed DAYS; unknown state is kept. Root, `devRoot`, land- and release-branch and locked worktrees are kept. Without a readable `scripts/agents/kit.json` it still lists (with a `problem:` line, no merge state) and refuses `--prune`. It runs `git worktree prune` and keeps branches.
- `scripts/agents/tickets.mjs frontier [map]` prints open wayfinder tickets with all blockers closed, including builder and title; `check` validates statuses and same-map blocker slugs in both `tickets/` and `build/tickets/`, and fails with `file:line`. Lint runs the check.
- `scripts/agents/review.sh <worktree> <brief-file> <out-dir> [--base REF]` is the older form of `kit review` (a thin wrapper that saves no main-root evidence); it wraps the agent runner in review mode; copies its invocation's `out.md` to `<out-dir>/result.md` and `run.log` there, and verifies `REVIEW_STATUS: complete`. Model and CLI overrides below apply.
- `scripts/agents/review-brief.sh <ticket-file> [base=origin/dev]` (`kit review --ticket` builds the same brief itself) prints the standard slice brief: diff scope, ticket/linked spec, standards, finding format and the author's validation contract. Review completion accepts the first non-blank line, stripping a leading BOM or markdown fence.
- `scripts/agents/agent.sh build|review <worktree> <brief> [--model M] [--cli codex|claude|grok|opencode] [--effort E] [--base REF] [--out DIR]` runs the selected agent; `agent.sh --resume <out-dir>` continues a stopped run. Defaults, adapters and resume below.
- `scripts/agents/sol.sh <worktree> <brief-file> [effort=medium]` is a compatibility wrapper for `agent.sh build`; model/CLI environment overrides apply. The runner prints its artifact directory.
- `scripts/agents/unit.sh [files...]` runs the given files, or the files `kit unit --list` selects from `unit.files`, through `unit.run`; prints pass/fail counts and each failure's name and first four error lines. Preserves the command's exit status; full log: `.scratch/unit/<time>-<pid>.log`. A test that never settles fails after `ASE_UNIT_TIMEOUT_MS` (default 120000), naming the test.
- `scripts/agents/shots.sh <out-dir> <scratch-spec.spec.ts>` (what `kit shots --spec` calls) runs only that `.scratch/` scenario through a dedicated Playwright config on a `port.sh` slot. Serves the real starter over fake GitHub, stops its server on completion/failure, and prints PNG paths. Fixture: `${ASE_NATIVE_SAVE_FIXTURE:-$HOME/Projects/native-site-editor-starter}`; screenshot destination: `ASE_SHOTS_OUT_DIR`. Example below.
- `scripts/agents/suite-summary.mjs <results.json> [...]` merges shard counts and prints each failure's file, line, title and first error line; labels and separately counts matches in [tests/known-failures.json](../../tests/known-failures.json) (or the registry at `ASE_KNOWN_FAILURES`) as known flaky or known failing on dev. It exits non-zero for every failure, report error or unreadable input. Registry titles match exactly and survive line moves; line-only entries cover parameterized tests, and spec-only entries cover the file.
- `scripts/agents/ci-fonts.conf` is a fontconfig with only DejaVu Sans, as on the CI runners; `FONTCONFIG_FILE=$PWD/scripts/agents/ci-fonts.conf` before a browser run uses it (cache in `~/.cache/fontconfig-ci`).
- `scripts/agents/land.sh` is replaced by `kit pr` and prints a notice pointing there. It still pushes straight to `dev` after check, test and lint; only the lead uses it, when `kit pr` cannot run.
- `scripts/agents/deploy-preview.sh` is a wrapper: `exec kit preview "$@"`.
- `scripts/agents/ci-status.sh [branch=dev]` prints the latest run per workflow and fails for unsuccessful completed runs, with failed steps and the last 20 log lines. To wait for CI, use `kit wait ci`.

## Agent runner

`agent.sh --resume <out-dir> --brief <file>` continues the recorded session with the file's text, including completed runs, preserving its model, CLI and effort; waits for a live runner first and appends to `run.log` and `out.md`.

Build and review default to `claude-opus-5-5`, effort `medium`. Set
`ASE_BUILD_MODEL` or `ASE_REVIEW_MODEL` to change the model. CLI precedence is
`--cli`, then `ASE_AGENT_CLI`, then model inference: `claude-*`, `opus`, `sonnet`,
`haiku`, `fable` select Claude; `grok-*` selects Grok and `opencode/<model>` OpenCode (both reviews only); all others select Codex. `--model` overrides the
kind's environment default. `--effort` is passed to the selected CLI; the CLI/model
validates its supported levels.

Every run writes `<out>/status.json` (pids, model, CLI, worktree, brief, state
`running`/`done`/`failed`/`timeout`/`interrupted`, exit code, session id). After a
crash or app restart, `agent.sh --resume <out-dir>` waits on a run that is still
alive, or continues its session (`codex exec resume`, `claude --resume`, `grok --resume` or `opencode run --session`) with
"Continue where you stopped; the brief is unchanged.", appending to `run.log` and
`out.md`. Codex reviews are not resumed (their private home holds credentials);
rerun them. `agent.sh` refuses a worktree that fails `kit doctor --quiet` (exit 3;
`ASE_SKIP_DOCTOR=1` is for tests). A build, or a resume whose `status.json` records `kind: build`, runs doctor with
`KIT_DOCTOR_SKIP=help`, so a broken `--help` does not stop the builder that should repair it
(`kit fix` starts its builder through `agent.sh`): the broken commands go to stderr as a
`problem: help:` line (plus `problem: kit home:` when the copied kit's `version` fails as its help did) and the build starts.
Reviews and a plain `kit doctor` still fail on it, and the agent itself runs without `KIT_DOCTOR_SKIP`.

Both modes read the brief on stdin with cwd set to the worktree. Build appends the
unstaged-work and validation contract. Every adapter verifies the actual model
(Codex's `model:` log line; Claude's JSON `modelUsage` keys or `model` field; Grok's
`modelUsage` keys, which may add a suffix such as `grok-4.7-build`; OpenCode's `opencode export --pure <session>`, where every
assistant message must be the requested `<provider>/<model>`; the export is skipped when the call failed (an error event, a non-zero exit or a timeout) and is
killed after `ASE_OPENCODE_EXPORT_TIMEOUT_MS`, default 60000, a value checked before the review starts).
An OpenCode call that names no session within `ASE_OPENCODE_START_TIMEOUT_MS` (default 300000) is stopped as `opencode unavailable: no session within <s>s`; a second look counts that as OpenCode being down.
Claude aliases permit their family; full names permit a dated snapshot suffix.
The `[1m]` context suffix is preserved for the CLI and ignored for model inference and verification.
Missing metadata, fallback models, CLI errors and empty reports fail the run.
Each invocation prints its directory at start, then writes `out.md` and `run.log`
in `<worktree>/.scratch/agent/<kind>-<time>-<pid>-<unique>/`. `--out DIR` selects
an invocation directory explicitly; callers must give each concurrent run its own directory.
Reviews also save `diff.patch`, `commits.log` and `refs.txt` for every adapter to read.
Scope defaults to `origin/dev`, or the brief's `git diff <base>...HEAD`; `--base REF` overrides it.
The runner prints the report and `git status --short`.

Codex build uses `workspace-write`, network access and `--add-dir` for the shared
Git directory; review uses `read-only`. Both automatically trust the vetted repo
hooks; interactive Codex asks once to approve new or changed hooks.
Claude build uses `acceptEdits`, allows Bash, denies Task/Agent, and adds the shared Git directory. Review uses
`plan` permissions, exposes only Read/Grep/Glob, excludes inherited settings with
`--setting-sources ""`, and disables MCP servers with `--strict-mcp-config`
and `--mcp-config '{"mcpServers":{}}'`. Claude returns JSON; the runner extracts
the result text. Grok reviews only: `--prompt-file /dev/stdin`, the `read-only`
sandbox, tools `read_file,grep,list_dir`, no subagents or web search, JSON output
whose `text` is the report; a session id is assigned up front (`-s`) and resumed
with `--resume`. OpenCode reviews only: `opencode run --pure --agent ase-review --format json -m <model> --dir <worktree>`
with the brief on stdin; `OPENCODE_CONFIG_CONTENT` defines `ase-review` with every permission denied but
read/grep/glob/list, and `OPENCODE_DISABLE_PROJECT_CONFIG=1` and `OPENCODE_DISABLE_CLAUDE_CODE=1` keep the
project's OpenCode config and Claude Code files out (the user's global `~/.config/opencode` config still loads, but its tools
are denied too); effort is not passed (a given `--effort`, as `kit ux` always sends, is ignored and `effort` is recorded as `null`), and a model without a
`provider/` part is refused before any call. The report is the text of the last
message in its JSON events; the session id comes from those events and is resumed with `--session`; `opencode export` writes to a
file, since through a pipe the CLI exits before a large export is written out. A failed CLI's own failure (timeout, out of credit, usage limit,
an OpenCode error event, else its exit status) is the last `problem:` line. The lead commits builders' unstaged work.

`ASE_AGENT_TIMEOUT` defaults to `90m`, with legacy `SOL_TIMEOUT` as fallback.
Use positive integer seconds or `s/m/h/d` (at most 2147483 seconds). Expiry or
interruption kills the CLI's whole process group. How callers wait:
[runner.md](runner.md#waiting).

To add another CLI, add one adapter function in `agent-run.mjs` and register it in
the adapter registry (plus inference if wanted). Contract:
accept `{kind, worktree, model, effort}`, Git common dir and output path; return
`{command, args, capture, finish(stdout, runLog)}`. Read stdin; honor build versus
read-only review permissions; verify the actual model in `finish`. Return final
text, or null if the CLI wrote `out.md`. Set `capture` for stdout parsing. Shared
code owns cwd, brief/footer, logging, deadlines, cleanup and Git status. Add pure
argument/result tests plus fake CLI coverage; no other CLIs are installed here.
Instruction imports use `AGENTS.md`: `CLAUDE.md` and `GEMINI.md` contain `@AGENTS.md`.

## Screenshots

`kit shots` covers the named screens and steps files. For anything else, write a raw
spec at `.scratch/shots.spec.ts`; `shots.sh` supplies `baseURL` and `ASE_SHOTS_OUT_DIR`.
Run `scripts/agents/kit shots --spec .scratch/shots.spec.ts` (or
`scripts/agents/shots.sh .scratch/shots/example .scratch/shots.spec.ts`).
This 20-line scenario saves the editor and its Add panel:

```ts
import { expect, test } from "@playwright/test";
import { join } from "node:path";

test("starter screenshots", { tag: "@actual" }, async ({ page }) => {
  const out = process.env.ASE_SHOTS_OUT_DIR;
  if (!out) throw new Error("Run through shots.sh");
  await page.goto("/#repo=501&branch=main&file=index.html");
  await expect(page.locator("#status")).toContainText("Up to date with main", { timeout: 30_000 });
  const preview = page.frameLocator(".native-preview-frame");
  await expect(preview.locator("body")).toBeVisible();
  await page.screenshot({ path: join(out, "editor.png"), fullPage: true });

  const structure = page.getByRole("complementary", { name: "Page structure" });
  await expect(structure).toBeVisible();
  await structure.getByRole("button", { name: "Add", exact: true }).click();
  const dialog = page.getByRole("dialog", { name: "Add to the page", exact: true });
  await expect(dialog).toBeVisible();
  await page.screenshot({ path: join(out, "add-panel.png"), fullPage: true });
  await dialog.getByRole("button", { name: "Close", exact: true }).click();
});
```

## Ports

Pool: eight slots, `5226 5236 5246 5256 5266 5276 5286 5296`. Each slot reserves its base port (native-save) and base + 1 (native-preview). `ASE_PORTS` selects only ports from this pool. Timing holds every pool lock, then `5216` (and checks `5217`); run cold measurements through `timing.sh`.

Gate: at least 4 GiB available memory and 1-minute load at most `nproc`; `ASE_MAX_LOAD` overrides the load limit. Unlocked slots with listeners are skipped, with PID/command when `ss -p` exposes them. Waiting reports memory, load or busy slots at most once per 60 seconds; busy locks report holder PID, cwd and command.

Ownership: lock files are `/tmp/ase-<base>.lock`, containing `pid cwd command`. `exec` keeps the lock and owner PID; the caller's process group owns its servers. Start a separate group (for example `setsid`) when you need to kill the whole run. Stop only your own processes. Test servers poll `ASE_TEST_OWNER_PID` every second and exit when the owner dies; demos without this variable retain their normal lifetime.

Reap: inspect `scripts/agents/reap.sh --dry-run` before cleaning leftovers. Default sends SIGTERM only to orphan listener PIDs and their descendants found through `/proc`, holding free slot locks during cleanup. Descendants are signalled before the listener. Ancestors and other process-group members survive; launcher wrappers may exit when their child dies. It covers pool base/+1 ports and `5216`/`5217`, preserves listeners outside unlocked slots and their descendants, and always leaves `5410` alone. It never expands the pool via `ASE_POOL`.

Tests: `ASE_LOCK_DIR` overrides `/tmp`; `ASE_POOL` is a test-only pool override for isolated high ports. Test-only `ASE_MIN_MEM_KB` overrides the 4194304 KiB memory threshold (`0` bypasses it); `ASE_PORT_POLL` overrides the 15-second resource/slot poll delay. Production runs use the fixed pool and default resource gates.

## Results

Each run of `full-suite.sh` writes to its own `.scratch/native-save/full-<time>-<pid>/` (printed at start): read `shard-k.log` there for progress, and `scripts/agents/suite-summary.mjs <run>/results-shard-*.json` for the combined result. Server output persists in `.scratch/<project>/server-<port>.log`, including stderr, even when the server dies. Configured JSON defaults to `.scratch/<selected-project>/results-<port>.json` (the first project, or native-save, for a multi-project run). CLI `--reporter` overrides the config: include `json` explicitly and set `PLAYWRIGHT_JSON_OUTPUT_FILE` to the desired path, as `full-suite.sh` does.

The layout comes from `scripts/agents/kit.json` (see [Kit](#kit)): worktrees are siblings named `<worktreePrefix><branch>` (slashes as dashes), the dev worktree is `devRoot` and the native-static fixture lives in the `mainRoot` checkout's `.scratch/native-static-preview`. This editor's values, for example, are `native-site-editor-`, `~/Projects/native-site-editor-dev` and `~/Projects/native-site-editor`.
