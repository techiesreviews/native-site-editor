# Agent scripts

Run from the worktree root; dependencies must already be installed.
The order runners use these in: [runner.md](runner.md).

Agent tool hooks and session Node PATH: see [Hooks](guardrails.md#hooks).

## Kit

`scripts/agents/kit <command> [args]` is the front door. Bare `kit` lists the commands;
`kit <command> --help` prints that command's usage and is the source of truth for its flags.
Every run ends with one `RESULT: ok|fail …` line (the kit adds one when a command does not, or
is interrupted); exit 0 ok, 1 failure, 2 usage error. Each command is one file in
`scripts/agents/kit.d/` with a `# kit: <summary>` line and its own `tests/kit-<command>.test.ts`;
shared helpers live in `kit-lib.sh` and `kit-lib.mjs`. Owner: `ASE_OWNER`, else `.scratch/owner`.

- `kit doctor [--quiet]` checks place, base, hook config, live hooks, Node, `node_modules` and conflict markers, each ✗ with a fix. Without `--quiet` it also notes whether the optional `grok` reviewer is installed and logged in (✓/✗ from `grok models`: logged in, not logged in, timed out, failed or unrecognised output; never a failure; `KIT_GROK` names another binary and `KIT_GROK_TIMEOUT` its timeout in seconds, default 10, for tests). The base passes when the branch contains `origin/dev`, or its base was the dev tip less than 24 hours ago ("N commits behind; rebase before landing"; `kit pr` rebases). `agent.sh` runs `--quiet` on its worktree and exits 3 on failure.
- `kit review [--base REF | --commit SHA] [--ticket FILE] [--pr N]` runs one read-only review (default `--base origin/dev`; model `ASE_REVIEW_MODEL`, else `claude-opus-5-5`: `claude-*` runs Claude, `grok-*` (e.g. `grok-4.7`) runs the `grok` CLI headless in its `read-only` sandbox with only read/grep/list tools, anything else runs Codex; Codex gets a fresh `CODEX_HOME` with no skills, plugins or MCP servers). Outside families have weekly budgets, counted per UTC ISO week in the main root `.scratch/review-budget.json`: `gpt` (Codex) `ASE_REVIEW_BUDGET_GPT=12`, `grok` `ASE_REVIEW_BUDGET_GROK=8`. It prints `budget: <family> <used>/<limit> in <week>`, waits up to `ASE_REVIEW_BUDGET_LOCK_MS` (10000) for the ledger lock, refuses at the limit (`problem: <family> review budget used up …; raise ASE_REVIEW_BUDGET_<FAMILY> to override`) and gives the reservation back when the CLI never started (empty diff or missing CLI) or when the provider refused the first call outright with a usage-limit message; any other started review counts even if it fails, times out or is refused on its completeness retry. Claude is never counted. Only `kit review` counts: `review.sh` and a direct `agent.sh review` skip the ledger. A provider usage-limit message ("You've hit your usage limit … try again at <time>") becomes `problem: <family> usage limit until <time>` when it is one of the CLI's last output lines. It saves `result.md`, `run.log`, `diff.patch`, `refs.txt` and `findings.json` in the main root `.scratch/reviews/<owner>/<UTC time>/`, named in the RESULT line, and prints a `findings N: <kind counts>; <severity counts>` line. `findings.json` is `{ model, effort, scope, head, findings: [{ group, severity, kind, text }], counts: { kind, severity } }` (validation gaps count as `gap` in both; severity `none` is a defect whose severity could not be read), or `{ model, effort, scope, head, unreadable: true }` when the report does not parse; `kit fix` appends `declined: [{ text, reason, round }]` from the builder's `Declined:` list (`- <finding> — reason: <why>`; an item without `— reason:` keeps its whole text and an empty reason); a retried round replaces its own entries. An empty diff fails before the model; an incomplete answer is re-asked once. Defects use `commit:path:line — P0/P1/P2/P3 <kind>: evidence and fix`, where kind is `fault` (the code is wrong), `ticket` (mismatch with the ticket or spec), `race` (timing, ordering or stale state) or `style` (standards or readability, no behaviour change); a missing or unknown kind is `unsorted` and blocks only by severity. P0 means data loss, security holes, broken build/tests or a wholly broken change; P1 means wrong user/runner behaviour or a broken ticket "Done when" item; P2 means a minor real defect; P3 means cosmetic/style. Validation gaps have no severity.
- `kit next [map…] [--start] [--max N]` hands out work by fixed rules: it reads the open frontier from `origin/dev` in the dev worktree (`KIT_DEV_ROOT`) and every worktree's running `slice-*` jobs (`kit bg --list`; each job's recorded `--ticket` gives its Files), then prints `running: <job> <ticket>`, `next: <ticket> builder=<model> owner=<owner> why=<slot>` and `waits: <ticket> <reason>` lines and `RESULT: ok next <n> ready, <m> waiting`. Rules, in order: only unclaimed `type: task (AFK)` tickets (a claimed one with no running slice prints `waits: … claimed by <owner>, no running job found`: a failed start or a delegated ticket), none from a map whose build README has a `**Not started:**` line above its first `##` heading; at most 5 running slices (`--max` lowers it; delegated picks take no slot); at most 2 in `src/main.ts`; no file shared with a running or newly picked slice (exact paths, dot folders such as `.github/` included; a plain word without backticks needs a path shape, so "and/or" is prose; a glob, placeholder or "find it with" line counts as its directory; `src/main.ts` is left to the previous rule); `runs_alone: true` waits for every other slice of its map and blocks new ones while it runs. Maps go in the order given, else alphabetical; tickets by number. Any malformed ticket in the loaded maps (all maps when none is named) stops the hand-out with `RESULT: fail next <n> ticket problems`; a job name `kit bg` would refuse waits for a `prefix:` line. Builders follow the [pins](kitchen.md#who-cooks-pins-from-2026-10-22): `claude`, `sol` or none → `claude-opus-5-5`, `opencode/<model>` → `delegate opencode/<model>` (T3 `delegate_task`), anything else as written. Owners are `<prefix>-<NN>` (the build README's `prefix:` line, else the map name; `<prefix>-m<NN>` for the map's own `tickets/`, which are numbered apart), and a job name already running or picked in the same run waits. `--start` claims each `next:` ticket on `dev` from the dev worktree (refuses unless it is on `dev`, clean and not ahead; fast-forwards, rechecks the ticket, fills `assignee:`, commits `docs: claim <map> <NN>`, pushes, and on a rejected push rebases and retries once; any failure before the push lands resets `dev` to `origin/dev`), then makes `build/<owner>-<slug>` with `worktree.sh` and starts `ASE_REVIEW_MODEL=claude-opus-5-5 kit bg slice-<prefix><NN> -- scripts/agents/kit slice --ticket … --builder <model>` there, printing its `wait: KIT_ROOT=<worktree> scripts/agents/kit wait job …` line; delegated tickets are only claimed (`delegate:` line). A start that fails after its claim landed ends `RESULT: fail next start <ticket>: claimed <sha> but not started: …`. Tickets of one map with the same `group:` are one hand-out: it waits (`waits: group <slug> tickets=… waits for <NN-slug> (blocked)`) until every member not closed or `wontfix` is open and blocked only by closed tickets or by members, then prints one `next: group <slug> tickets=<a,b,c> builder=… owner=<prefix>-g-<slug> why=…` line with the tickets in `blocked_by` order; it counts once toward the cap, the union of its Files meets the `src/main.ts` and shared-file rules, and members needing Lex, differing builders, a partial claim or a `blocked_by` cycle make it wait. `--start` claims all its tickets in one commit (`docs: claim <map> group <slug>`), makes `build/<prefix>-g-<slug>` and starts one `kit bg slice-<prefix>g-<slug> -- scripts/agents/kit next --run-group --branch build/<prefix>-g-<slug> --builder <model> --ticket … --ticket …` job, which runs `kit slice` for each ticket in order in that worktree (one model, a fresh builder session per slice) and stops at the first failure or a dirty worktree; the first slice runs on `--branch`, each later one on a new branch `<branch>-<NN>` (`m<NN>` for a map ticket) from the fetched `origin/dev`, as `kit pr` rebase-merges and deletes the last one. To resume a stopped group, rerun the job's command (`kit bg` with the same name and command): it skips tickets closed on `origin/dev` or merged by their saved slice (`.scratch/kit-slice/<slug>/state.json` with `pr` finished) and returns a slice with saved state to its branch. Before claiming, a group is rechecked on the fast-forwarded dev: a member claimed meanwhile, joining or leaving, newly blocked, or with a changed builder or type leaves the group unclaimed, and a lone ticket that gained `group:` meanwhile is not claimed alone (`claimed meanwhile (group changed)`).
- `kit slice --ticket FILE --builder MODEL [--effort high] [--rounds 3] [--no-pr]` writes the brief, builds (`sol` = `gpt-6.1-sol`), commits through normal Git hooks, reviews, fixes up to three rounds and lands via `kit pr`; start under `kit bg` and wait once. Reruns resume saved phases in `.scratch/kit-slice/<ticket-slug>/`, re-reviewing moved HEADs unless only the ticket changed since the covering review; a rerun may name another `--builder` or `--effort`, keeping finished phases, recording the old model in `previousModels` (or effort in `previousEfforts`), printing `builder switched: <old> -> <new>` and passing the new model and effort to later fix rounds (a fix round paused in its commit or review step first finishes under its saved model), while a different ticket or branch still refuses. Failures show at most 15 log lines. Every finding blocks before three completed fix rounds; afterwards only P0/P1 defects, defects without readable severity and unreadable reviews block, while P2/P3 defects and validation gaps proceed to `kit pr` as follow-ups. `--no-pr` stops after the review/fix gate; the slice never passes `--waive`. Fresh slices require a clean worktree; existing slices may resume pending changes. A queued slice refuses `--no-pr` if local HEAD moved. Queued PRs are saved and awaited until merged (two-hour timeout; retries resume the wait); unexpected PR failures keep their bounded PR log digest. Its builder brief forbids landing and nested agent commands, requires focused unit checks, and reserves review decisions and landing records for the slice.
- `kit fix [--review DIR | --note FILE] [--run DIR] [--ticket FILE] [--builder MODEL] [--effort E]` sends the newest review covering HEAD, or a verbatim failure note instead, to this worktree's latest resumable builder, commits its fixes with model credit, and reviews again with declined findings and reasons. Without a resumable run it announces a fresh `agent.sh build`, using `--builder MODEL` and `--effort E` (default: the latest matching slice state's model and effort, else `claude-opus-5-5` and `high`; `sol` expands to `gpt-6.1-sol`; with `--builder` and/or `--effort`, only a saved session of the named model and/or effort resumes, otherwise it starts fresh with them). An explicit `--run DIR` that is missing, unreadable or belongs to another worktree errors; one of another model or effort is named on the `--run ... is ...; starting fresh with ...` line, and a fresh builder starts with the requested setting and that run's other one. A pending round still in its builder step switches to a requested model or effort, keeps its edits and brief, and prints `builder switched: <old> -> <new>`; a pending commit or review round still refuses. Ticket defaults to the builder brief's ticket path, then the latest matching slice state's ticket; otherwise pass `--ticket FILE`. Fresh builder records live in `.scratch/agent/build-*` so later rounds discover and resume the same session and model; discovery compares run start times across normal and slice builders. Branch rounds live in `.scratch/kit-fix/<encoded-branch>/round-N.md`. A branch-local `pending.json` saves the current builder/commit/review step; retries reuse that round, preserve edits and declined reasons, and validate its captured HEAD before continuing.
- `kit pr [--base dev] [--title T] [--ticket FILE] [--no-merge] [--dry-run] [--release] [--full] [--waive "<reason>"]` lands a branch. It refuses a detached HEAD, `dev`/`main`, a dirty tree and `--base main` without `--release`; runs `kit deps check`, rebases on `origin/<base>`, then prints `tier: <tier> (<why>)` for the PR's own diff and runs that tier's checks (`--dry-run` stops here). Tiers, highest present wins ([pr-tier.mjs](../../scripts/agents/pr-tier.mjs)): **docs** (only `*.md` and `docs/**`) runs `tickets.mjs check`, the doc-reading guard unit files and any unit file naming a changed docs path, with no review; **css** (only existing `*.css`) runs `check-colours.mjs` and `kit specs --affected`, and reminds you about `kit shots`; **tests** (only `tests/**`, `fixtures/**`) runs `npm run check`, the changed unit files plus those naming a changed helper or fixture (`unit.sh`), `npm run lint` and `kit specs --affected`; **full** (anything else, or `--full`) runs `npm run check`, `npm test`, `npm run lint` and `kit specs --affected`. The tier and skipped checks go in the PR body; CI still runs everything. It pushes, opens or reuses the PR, posts the newest completed saved review covering this HEAD and merge base (also covers a descendant when only the `--ticket` file changed), or a clean review whose recorded refs produce the same `git patch-id --stable` as the current whole PR diff (prints `review: reused (same patch on new base)`; changed patches, including changed conflict resolutions, require a new review; missing refs and empty patch IDs cannot establish reuse; else runs `kit review --pr N`; not for docs), stops before CI or merge on any open finding before three completed branch fix rounds, then only on P0/P1 defects, defects without readable severity or unreadable reviews. After three rounds P2/P3 defects and validation gaps become follow-ups in a PR comment/body and, with `--ticket`, its Done section in a new commit; that ticket-only commit retains review coverage. Only a `*-lead` owner may override blockers with `--waive "<reason>"`, recorded separately in a PR comment and body; otherwise waits with `kit wait ci --pr N`, and rebase-merges pinned to that head, deleting the branch. A "behind" refusal rebases and retries up to 3 times. `--release` opens `dev` → `main` and never merges. The `gh` token needs Pull requests: Read and write ([github-settings.md](github-settings.md)).
- `kit bg <name> [--cwd DIR] -- <command…>` starts a detached named job with `setsid` + `nohup`, stdin `/dev/null`, its own process group and records/logs in `.scratch/kit-jobs/<name>/`; `--list` shows state, age and log path; `--stop <name>` sends SIGTERM to its group and SIGKILL after 2s if needed. Live names are refused; finished records are replaced.
- `kit wait job <name> [--timeout D]` waits from recorded job files, including after a restart; prints at most 15 log-tail lines plus the job's last `RESULT:` and returns its exit status. A dead job without an exit record fails with 1; timeout while still running returns 124 (safe to wait again).
- `kit wait pid <pid>`, `kit wait output <file> [--until RE] [--quiet D]` and `kit wait ci [--branch B | --pr N | --sha S]`, each with `--timeout D` (default 30m), wait on a process, a log (until the regex, or until its writers exit and it stays unchanged for 5 s; prints its last 20 lines) or the CI runs of one head (failed steps, up to 10 failing test lines with source and first error, then the last 20 log lines; a cancelled run on a moved head is followed as "superseded"). At most one status line a minute.
- `kit specs <spec…> | --affected [--base REF]` with `[--list]` runs browser specs by name, or those a diff against the merge-base reaches (reasons: import, fixture, removed string, defined string, name match; `--list` prints them and runs nothing). Each fixture group runs through `port.sh`; one ✓/✗ line per spec with known-failure labels from `ASE_KNOWN_FAILURES` (default `tests/known-failures.json`). Failures add a digest for up to 10 failing tests, at most 10 lines each: message, expected/received, first app/test stack frame and log/context/trace paths. Retried passes are excluded; further failures are counted. Logs: `.scratch/kit-specs/run-*/`.
- `kit unit [files…] | --affected [--base REF]` with `[--list]` runs unit files through `unit.sh` (all when no files); affected selection uses the merge-base with `origin/dev` by default, plus staged, unstaged and untracked files, following imports transitively and printing `changed`, `imports` or `via` reasons. `--list` runs nothing; docs-only changes report `unit none affected`. Results include pass/total, file count and the `.scratch/unit/` log.
- `kit shots <screen…> | --steps FILE | --spec FILE` with `[--width W,…] [--theme T] [--out DIR] [--compare REF] [--files]` shoots named screens (13; bare `kit shots` lists them; steps files live in `.scratch/` or `scripts/agents/shots/features/`; steps include `drag … edge`, `record <name> <ms>` (an 8-frame strip) and `expect visible`) on the real starter over fake GitHub, 390/768/1280 × light/dark by default, a failed screen retaken once. Output in the main root `.scratch/shots/<owner>/<time>/`: PNGs, webp copies under 40 KB, `contact.html`/`contact.webp` (numbered `contact-N.*` when split by whole screen rows; each sheet ≤1600 × 2400 px and ≤300 KB), `index.json`, and up to 20 layout findings (clipped, overlap, tap-target, contrast, overflow). Contact paths print first and appear in RESULT; default output lists the file count and index, `--files` lists every path. `--compare` shoots the ref with today's tooling from a cached base worktree and pairs before | after rows.
- `kit ux [--base REF] [--features F-…,…] [--all] [--no-review] [--ticket FILE]` matches the diff against the merge-base (default `origin/dev`, plus uncommitted and untracked files) with each feature's `Files` globs in [features.md](features.md) (`--features` or `--all` override; none touched is `RESULT: ok ux nothing visible touched`), runs each touched feature's steps file (`scripts/agents/shots/features/<id>.json`) through `kit shots --steps` at 1280 px, plus 390 px for `Phone: yes`, light and dark, and gives a feature without one the named screens its files map to, marked untried. Scripted checks: layout findings, tap targets under 44 px at 390, raw colours in changed CSS, new visible text over 60 characters and new hint, tip, count or badge class names (S1, S2), and raw px spacing and timings in changed CSS counted against the base (reported, not blocking). The bundle in the main root `.scratch/ux/<owner>/<time>-XXXXXX/` is `bundle.md` (diff summary, features with Try/Good, the rules they cite, findings with file and line or screenshot, tries, the ticket's mock-up link; under 60 KB) and at most 12 images of at most 300 KB (contact sheets and `record` strips); it trims the lowest-value items first and says what; raw tries stay in `.scratch/ux-tries/<owner>/<time>-XXXXXX/`. `RESULT: ok ux <n> features tried, <m> scripted findings, bundle <dir>`; a failed try fails with `broken: <feature,…>`. The model review is a later slice (`--no-review` changes nothing yet).
- `kit size [--no-base] [--base REF]` builds and measures boot bytes before first paint against the base (default `origin/dev`) and fails above the 362 KB budget. Per-commit cache: main root `.scratch/size-cache/`.
- `kit deps check [--lock F] [--modules D]` compares the shared `node_modules` with the lockfile; `kit deps add <pkg>[@version] [--dev]` adds a package without npm ever writing to the shared folder.
- `kit score [map] [--json] [--snapshot]` prints the scoreboard: one row per piece (builder, minutes, review rounds, findings by kind, build cost, review cost, PR; `#N open` until merged), then totals per builder (the model that did the build; a row reads `<built> -> <current>` when fix rounds switched builder) and per kind of job; with no map, every map with records. Records live in the main root `.scratch/scoreboard/<map>/<ticket-slug>.json` (map = the ticket's `docs/wayfinder/<map>/` folder; other tickets and runs without `--ticket` go under `_untracked/`, the latter as `<encoded-branch>.json`), written atomically under a `<record>.lock` folder (its `owner` file names the pid; waits up to `ASE_SCORE_LOCK_MS`, default 5000, and takes over a lock whose owner died or that is older than ten waits, at least 10 s) by `kit slice` (builder `{ model, effort, previousModels, built }`, each phase's `{ name, start, end, exit }`, rounds, reviews, build cost, merge), `kit fix` (each round, a switched builder with the old model in `previousModels`, its builder's cost, declined findings), `kit review` (each review's `{ dir, model, effort, counts, declined }` from `findings.json`) and `kit pr` (`landed: { pr, tier, ci, sha, at, waived, queued }`; a new PR number starts a fresh `landed`, and the slice keeps the full SHA and time `kit pr` recorded; with a merge queue `kit pr` records only `queued: true`, and the merge SHA and time are filled in only by a `kit slice` waiting on that PR, and `queued: true` stays beside them as history). `cost` is `{ build, review }`, each `{ usd, tokens }` (or `null`) summing what that role's runs reported (Claude/Grok JSON `total_cost_usd` and token usage, Codex `tokens used` lines); never guessed; `partial: true` (shown `>=$`) marks dollars that leave out runs which reported tokens only, and the row shows dollars and tokens side by side. Minutes sum phase durations, so pauses between reruns do not count; a queued slice's `pr` phase includes its merge-queue wait. A record that cannot be written prints one `problem: scoreboard …` line and never fails the command. `--json` prints `{ map, pieces, totals: { builders, kinds }, feedback }` (no map: `{ maps: [...] }`; folders relative to the main root; `feedback` is `build/feedback.md` when present, else `null`); `--snapshot` writes the same object to `docs/wayfinder/<map>/build/scoreboard.json` for the lead to commit at the end of a build (with `--json` its `snapshot:` line goes to stderr, so stdout is the data and the RESULT line). A map with no records prints `score: <map> (0 pieces)`.
- `kit status [map] [--ref REF] [--no-fetch]` prints one row per ticket (status, owner, LANDED commit and PR, CI) under a header with the ref's CI and the live preview bundle; offline it still prints the git table.
- `kit feedback <map> --kind K [--after-release] [--fix <ticket|PR>] "<text>"` adds one line of Lex's feedback, newest first, to `docs/wayfinder/<map>/build/feedback.md` (creating it with its heading and legend) and prints it as `file:line: <line>`; `kit feedback <map> --fix-for <line-number> <ticket|PR>` fills that line's fix later. Kinds: `too-much`, `below-bar`, `felt-wrong`, `fault`, `workflow`; a fix is a ticket number in the map's `build/tickets/` or `tickets/` (written as a link; a number in both is refused, so name one as `24-slug`, `tickets/24-slug` for the build or `../tickets/24-slug` for the map) or a PR (`#12`, written `PR #12`). `--` ends the flags. It never commits; a bad kind or other bad input exits 2. `tickets.mjs check` validates every log line.
- `kit preview [--dry-run]` is for the lead: deploys `origin/dev` from the main root `.scratch/preview-deploy` worktree under a lock and checks the live bundle (`RESULT: ok preview <version-id> <sha>`). Git steps time out after 2m, deploy after 10m, verification after 2m; `ASE_PREVIEW_TIMEOUT` overrides these with positive integer seconds or `s/m/h` (at most 2147483 seconds; invalid values exit 2). A subprocess deadline sends SIGTERM to the step's process group, then SIGKILL after 500ms, waits for its exit, removes `dist/` and `.wrangler/tmp/`, and releases the lock (`RESULT: fail preview <step> timed out after <duration> (killed pgid <pid>)`).
- `kit card` prints Lex's [context card](context-card.md) for this worktree from `~/Projects/chat/memory/` (`CHAT_MEMORY_DIR` overrides): current thinking, newest 5 decisions, open questions, a 14-day corrections count and "More: ask for the full note.", at most 30 lines of at most 160 characters; no notes prints `context card: no notes for this project yet`.
- `kit version` prints the kit's commit, owner and Node version.

## Other scripts

- `scripts/agents/port.sh <cmd...>` waits for resources, locks a free slot, and sets `ASE_TEST_PORT`. Port rules below.
- `scripts/agents/timing.sh <cmd...>` holds all eight focused slot locks, then `5216`, for an exclusive timing run.
- `scripts/agents/cold.sh <worktree> <outprefix>` serves existing `dist` on `5216`, records the served index asset, measures five cold/warm runs with `ASE_COLD_NET=100/20`, waterfall and JSON; run through `timing.sh`.
- `scripts/agents/full-suite.sh [shards=3]` runs native-save shards in parallel with one worker each, separate artifacts, line logs and JSON; caps shards to currently free slots (at least one), prints the count, waits, summarizes, and fails if any shard fails. Each shard acquires any eligible slot through `port.sh`. `ASE_SHARDS` sets the default. Allow 25–50 minutes with 3 shards on a busy machine.
- `scripts/agents/reap.sh [--dry-run]` kills orphan test servers on unlocked slots; `--dry-run` lists them.
- `scripts/agents/worktree.sh <branch> [base=origin/dev]` creates a sibling worktree with shared dev `node_modules` and native-static fixture symlinks; records UTC time, `${ASE_OWNER:-unknown}`, branch and base in `.scratch/owner`, then prints its path. Set `ASE_OWNER` to the agent/thread identifier.
- `scripts/agents/worktrees.sh [--prune] [--older-than DAYS=3]` lists registered paths, branches, owners, dirtiness, commit age, merge state against local `origin/dev` or `origin/main`, and live cwd state from `/proc`. Listing is the default. Prune removes only clean, merged, inactive worktrees whose commit and creation ages exceed DAYS; unknown state is kept. Root, dev and locked worktrees are kept. It runs `git worktree prune` and keeps branches.
- `scripts/agents/tickets.mjs frontier [map]` prints open wayfinder tickets with all blockers closed, including builder and title; `check` validates statuses and same-map blocker slugs in both `tickets/` and `build/tickets/`, and fails with `file:line`. Lint runs the check.
- `scripts/agents/review.sh <worktree> <brief-file> <out-dir> [--base REF]` is the older form of `kit review` (a thin wrapper that saves no main-root evidence); it wraps the agent runner in review mode; copies its invocation's `out.md` to `<out-dir>/result.md` and `run.log` there, and verifies `REVIEW_STATUS: complete`. Model and CLI overrides below apply.
- `scripts/agents/review-brief.sh <ticket-file> [base=origin/dev]` (`kit review --ticket` builds the same brief itself) prints the standard slice brief: diff scope, ticket/linked spec, standards, finding format and the author's validation contract. Review completion accepts the first non-blank line, stripping a leading BOM or markdown fence.
- `scripts/agents/agent.sh build|review <worktree> <brief> [--model M] [--cli codex|claude|grok] [--effort E] [--base REF] [--out DIR]` runs the selected agent; `agent.sh --resume <out-dir>` continues a stopped run. Defaults, adapters and resume below.
- `scripts/agents/sol.sh <worktree> <brief-file> [effort=medium]` is a compatibility wrapper for `agent.sh build`; model/CLI environment overrides apply. The runner prints its artifact directory.
- `scripts/agents/unit.sh [files...]` runs all unit tests via `npm test`, or selected files via `tsx --test`; prints pass/fail counts and each failure's name and first four error lines. Preserves the command's exit status; full log: `.scratch/unit/<time>-<pid>.log`. A test that never settles fails after `ASE_UNIT_TIMEOUT_MS` (default 120000), naming the test.
- `scripts/agents/shots.sh <out-dir> <scratch-spec.spec.ts>` (what `kit shots --spec` calls) runs only that `.scratch/` scenario through a dedicated Playwright config on a `port.sh` slot. Serves the real starter over fake GitHub, stops its server on completion/failure, and prints PNG paths. Fixture: `${ASE_NATIVE_SAVE_FIXTURE:-$HOME/Projects/native-site-editor-starter}`; screenshot destination: `ASE_SHOTS_OUT_DIR`. Example below.
- `scripts/agents/suite-summary.mjs <results.json> [...]` merges shard counts and prints each failure's file, line, title and first error line; labels and separately counts matches in [tests/known-failures.json](../../tests/known-failures.json) (or the registry at `ASE_KNOWN_FAILURES`) as known flaky or known failing on dev. ## Agent runner

`agent.sh --resume <out-dir> --brief <file>` continues the recorded session with the file's text, including completed runs, preserving its model, CLI and effort; waits for a live runner first and appends to `run.log` and `out.md`.

Build and review default to `claude-opus-5-5`, effort `medium`. Set
`ASE_BUILD_MODEL` or `ASE_REVIEW_MODEL` to change the model. CLI precedence is
`--cli`, then `ASE_AGENT_CLI`, then model inference: `claude-*`, `opus`, `sonnet`,
`haiku`, `fable` select Claude; `grok-*` selects Grok (reviews only); all others select Codex. `--model` overrides the
kind's environment default. `--effort` is passed to the selected CLI; the CLI/model
validates its supported levels.

Every run writes `<out>/status.json` (pids, model, CLI, worktree, brief, state
`running`/`done`/`failed`/`timeout`/`interrupted`, exit code, session id). After a
crash or app restart, `agent.sh --resume <out-dir>` waits on a run that is still
alive, or continues its session (`codex exec resume`, `claude --resume` or `grok --resume`) with
"Continue where you stopped; the brief is unchanged.", appending to `run.log` and
`out.md`. Codex reviews are not resumed (their private home holds credentials);
rerun them. `agent.sh` refuses a worktree that fails `kit doctor --quiet` (exit 3;
`ASE_SKIP_DOCTOR=1` is for tests).

Both modes read the brief on stdin with cwd set to the worktree. Build appends the
unstaged-work and validation contract. Every adapter verifies the actual model
(Codex's `model:` log line; Claude's JSON `modelUsage` keys or `model` field; Grok's
`modelUsage` keys, which may add a suffix such as `grok-4.7-build`).
Claude aliases permit their family; full names permit a dated snapshot suffix.
The `[1m]` context suffix is preserved for the CLI and ignored for model inference and verification.
Missing metadata, fallback models, CLI errors and empty reports fail the run.
Each invocation prints its directory at start, then writes `out.md` and `run.log`
in `<worktree>/.scratch/agent/<kind>-<time>-<pid>-<unique>/`. `--out DIR` selects
an invocation directory explicitly; callers must give each concurrent run its own directory.
Reviews also save `diff.patch`, `commits.log` and `refs.txt` for every adapter to read.
Scope defaults to `origin/dev`, or the brief's `git diff <base>...HEAD`; `--base REF` overrides it.
The runner prints the report and `git status --short`.

Codex build uses `workspace-write`, network access and `--add-dir` for the shared
Git directory; review uses `read-only`. Both automatically trust the vetted repo
hooks; interactive Codex asks once to approve new or changed hooks.
Claude build uses `acceptEdits`, allows Bash, denies Task/Agent, and adds the shared Git directory. Review uses
`plan` permissions, exposes only Read/Grep/Glob, excludes inherited settings with
`--setting-sources ""`, and disables MCP servers with `--strict-mcp-config`
and `--mcp-config '{"mcpServers":{}}'`. Claude returns JSON; the runner extracts
the result text. Grok reviews only: `--prompt-file /dev/stdin`, the `read-only`
sandbox, tools `read_file,grep,list_dir`, no subagents or web search, JSON output
whose `text` is the report; a session id is assigned up front (`-s`) and resumed
with `--resume`. A failed CLI's own failure (timeout, usage limit or exit status)
is the last `problem:` line. The lead commits builders' unstaged work.

`ASE_AGENT_TIMEOUT` defaults to `90m`, with legacy `SOL_TIMEOUT` as fallback.
Use positive integer seconds or `s/m/h/d` (at most 2147483 seconds). Expiry or
interruption kills the CLI's whole process group. How callers wait:
[runner.md](runner.md#waiting).

To add another CLI, add one adapter function in `agent-run.mjs` and register it in
the adapter registry (plus inference if wanted). Contract:
accept `{kind, worktree, model, effort}`, Git common dir and output path; return
`{command, args, capture, finish(stdout, runLog)}`. Read stdin; honor build versus
read-only review permissions; verify the actual model in `finish`. Return final
text, or null if the CLI wrote `out.md`. Set `capture` for stdout parsing. Shared
code owns cwd, brief/footer, logging, deadlines, cleanup and Git status. Add pure
argument/result tests plus fake CLI coverage; no other CLIs are installed here.
Instruction imports use `AGENTS.md`: `CLAUDE.md` and `GEMINI.md` contain `@AGENTS.md`.

## Screenshots

`kit shots` covers the named screens and steps files. For anything else, write a raw
spec at `.scratch/shots.spec.ts`; `shots.sh` supplies `baseURL` and `ASE_SHOTS_OUT_DIR`.
Run `scripts/agents/kit shots --spec .scratch/shots.spec.ts` (or
`scripts/agents/shots.sh .scratch/shots/example .scratch/shots.spec.ts`).
This 20-line scenario saves the editor and its Add panel:

```ts
import { expect, test } from "@playwright/test";
import { join } from "node:path";

test("starter screenshots", { tag: "@actual" }, async ({ page }) => {
  const out = process.env.ASE_SHOTS_OUT_DIR;
  if (!out) throw new Error("Run through shots.sh");
  await page.goto("/#repo=501&branch=main&file=index.html");
  await expect(page.locator("#status")).toContainText("Up to date with main", { timeout: 30_000 });
  const preview = page.frameLocator(".native-preview-frame");
  await expect(preview.locator("body")).toBeVisible();
  await page.screenshot({ path: join(out, "editor.png"), fullPage: true });

  const structure = page.getByRole("complementary", { name: "Page structure" });
  await expect(structure).toBeVisible();
  await structure.getByRole("button", { name: "Add", exact: true }).click();
  const dialog = page.getByRole("dialog", { name: "Add to the page", exact: true });
  await expect(dialog).toBeVisible();
  await page.screenshot({ path: join(out, "add-panel.png"), fullPage: true });
  await dialog.getByRole("button", { name: "Close", exact: true }).click();
});
```

## Ports

Pool: eight slots, `5226 5236 5246 5256 5266 5276 5286 5296`. Each slot reserves its base port (native-save) and base + 1 (native-preview). `ASE_PORTS` selects only ports from this pool. Timing holds every pool lock, then `5216` (and checks `5217`); run cold measurements through `timing.sh`.

Gate: at least 4 GiB available memory and 1-minute load at most `nproc`; `ASE_MAX_LOAD` overrides the load limit. Unlocked slots with listeners are skipped, with PID/command when `ss -p` exposes them. Waiting reports memory, load or busy slots at most once per 60 seconds; busy locks report holder PID, cwd and command.

Ownership: lock files are `/tmp/ase-<base>.lock`, containing `pid cwd command`. `exec` keeps the lock and owner PID; the caller's process group owns its servers. Start a separate group (for example `setsid`) when you need to kill the whole run. Stop only your own processes. Test servers poll `ASE_TEST_OWNER_PID` every second and exit when the owner dies; demos without this variable retain their normal lifetime.

Reap: inspect `scripts/agents/reap.sh --dry-run` before cleaning leftovers. Default sends SIGTERM only to orphan listener PIDs and their descendants found through `/proc`, holding free slot locks during cleanup. Descendants are signalled before the listener. Ancestors and other process-group members survive; launcher wrappers may exit when their child dies. It covers pool base/+1 ports and `5216`/`5217`, preserves listeners outside unlocked slots and their descendants, and always leaves `5410` alone. It never expands the pool via `ASE_POOL`.

Tests: `ASE_LOCK_DIR` overrides `/tmp`; `ASE_POOL` is a test-only pool override for isolated high ports. Test-only `ASE_MIN_MEM_KB` overrides the 4194304 KiB memory threshold (`0` bypasses it); `ASE_PORT_POLL` overrides the 15-second resource/slot poll delay. Production runs use the fixed pool and default resource gates.

## Results

Each run of `full-suite.sh` writes to its own `.scratch/native-save/full-<time>-<pid>/` (printed at start): read `shard-k.log` there for progress, and `scripts/agents/suite-summary.mjs <run>/results-shard-*.json` for the combined result. Server output persists in `.scratch/<project>/server-<port>.log`, including stderr, even when the server dies. Configured JSON defaults to `.scratch/<selected-project>/results-<port>.json` (the first project, or native-save, for a multi-project run). CLI `--reporter` overrides the config: include `json` explicitly and set `PLAYWRIGHT_JSON_OUTPUT_FILE` to the desired path, as `full-suite.sh` does.

The scripts assume Lex's layout: worktrees are siblings named `native-site-editor-*` under `~/Projects`, the dev worktree is `~/Projects/native-site-editor-dev`, and the native-static fixture lives in the root checkout's `.scratch/native-static-preview`.
