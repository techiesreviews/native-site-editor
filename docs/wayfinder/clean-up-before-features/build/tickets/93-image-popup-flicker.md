## Goal

A defect Lex found ([ticket 04](../../tickets/04-grill-debt-and-fix-choices.md#comments), round 1): editing an image with the edit bar's Image popup, for example zooming in and moving the picture to the side, redraws the image and it flickers. Diagnose first, then fix.

## Decided behaviour

[Ticket 04](../../tickets/04-grill-debt-and-fix-choices.md#resolution-2026-10-22): the Image edit bar's redraw and flicker while zooming or moving goes into the plan as a diagnose-and-fix slice. While Lex zooms, turns or moves a picture in the Image popup (and in the large editor), the picture on the page and in the popup's previews changes smoothly, with no blank frame, no reload of the picture and no jump. What each change does is unchanged (the popup applies at once; closing writes one Undo step).

Exception to CODING_STANDARDS.md › Racing and speculative reads (runner-93, review round 4; for the lead to confirm): the page's look is a stream of steps, not one result. An older step whose picture decodes before any newer step has shown is still shown, and the newer step replaces it when its own decode ends, so a drag keeps moving instead of waiting until it stops. Once a newer step has shown, older ones write nothing, and nothing writes after Close. The final picture is always the newest step's.

## Where to look (not a diagnosis)

The popup shows each change at once through an `image-look` message to the preview (`src/components/native-preview-runtime.js` around 3825), and the popup draws its own previews (`src/page-builder/image-popup-view.ts`, `trimmedPreview`, `loadPicture`). Candidates: the look replacing the image's `src` or element on each step, a new object URL per step, previews rebuilt per input event, or a draft write and preview repaint per step.

## Done (2026-10-22)

**Cause.** Every zoom, turn or move step sends one `image-look` per frame. The canvas handler (`setImageLook` in `src/components/native-preview-runtime.js`) first put all of the image's own attributes back (its own `src` and `style`), then set the new trimmed picture. So between two steps the image was given its uncropped picture and then a new data address it still had to decode; the browser kept drawing the image's own picture, in the trim's style, until the new one was ready: the flick back and jump Lex saw. Evidence: on `dev` each step calls `setAttribute("src", <own picture>)` before `setAttribute("src", <next trim>)`. The new spec records every `src` set on the page's image; run against the `dev` runtime and popup view it fails (`kit specs native-image-popup.spec.ts`: `RESULT: fail specs 1 of 1 failed`, at the assertion that the own picture, a `data:image/webp` address, never returns after the first trim). With the fix it passes (`RESULT: ok specs 1/1 passed`, 22 tests in the file at the fix commit; 33 after review round 4).

**Behaviour.** A new look on the same image changes only what differs: attributes it keeps setting are not put back in between, and only ones it no longer sets come back. A new picture is decoded first (`Image.decode`) and then shown together with its style, so the trimmed picture already showing stays until the next one can be drawn. If a later look shows first, the older one is dropped. A page render still puts the image's own attributes back and reads them again, as before; what the look last showed (its trim and style, already decoded) goes back in the same task, with no frame of the page's own picture between, even while the next trim is still decoding (an edit, or Close's write right after a step). A decode that fails still shows its picture, as the page would; one that never settles is overtaken by the next look or Close. A look that shows writes onto the newest look's record, saving any attribute it adds, so Close puts every one back. In the previews, a picture that fails to load drops the checkerboard mark of the one before. Closing the popup still gives the image its own attributes back. In the popup's small previews, a picture that may be see-through keeps its checkerboard mark until the new trim has loaded, so it no longer flashes on each step.
