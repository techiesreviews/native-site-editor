# Editor CSS on the Techies Framework layers

Lex, 2026-11-11 (Orbit TOOLS-207): direct access to all the CSS of a component, one file per component with its own
defaults, edited in CSS on the design board, with layers deciding which rule wins. This plan maps today's CSS onto
the layers and orders the slices. The pilot (the Button) is built; the rest are later slices.

## The layers

The Techies Framework (generated by techies.tools, source in `~/Projects/TechiesTools`) ships `tokens.css`,
`elements.css` and `components.css` under `@layer tokens, elements, components;`. The editor keeps its own files
under the same names; the generated framework files are never edited by hand (they are not round-trippable), and
`scripts/tokens-from-framework.mjs` keeps turning the framework's tokens into `src/theme.css`.

| Layer | What sits there | Wins over |
| --- | --- | --- |
| `tokens` | Custom properties on `:root`: colours, spacing, type, corners, shadows, timings, layers | nothing |
| `elements` | Bare HTML (`button`, `select`, `a`, headings, the reset), no classes | tokens |
| `components` | One file per component in `src/ui/parts/<name>.css`, each with its own `--<name>-*` defaults | elements |
| editor (unlayered) | Screen layout and one-off placement: the top bar, workspace, sidebar, login, panels, sheets | every layer |

Rules that matter for every slice:

- **Unlayered CSS beats every layer, whatever its specificity.** A screen that needs a component to differ sets one
  of its `--<name>-*` properties, or writes a rule, in its own unlayered CSS. A component never needs a stronger
  selector to win over an element rule.
- **The order statement comes first.** `src/style.css` starts with `@layer tokens, elements, components;`, and every
  component file starts with the same line, so the order holds wherever a file loads (a lazy panel's CSS included).
- **The editor's entry loads each component file.** `src/main.ts` imports it, never `src/style.css` or the part's own
  module: the board loads the same file as a style of its own (`src/catalogue/component-css.ts`), so a live cell can
  leave it out.
- **One component, one file, one block.** `src/ui/parts/<name>.css` holds the order line, then one
  `@layer components { … }` with native nesting: the root rule sets the `--<name>-*` defaults and uses them; a tone or
  size changes only those properties; hover sits behind `@media (hover: hover) and (pointer: fine)`, touch gets
  `:active`. The Framework's `.btn` is the shape to follow.
- **The look stays the same.** Each slice moves rules without changing what anyone sees: `kit shots --compare dev`
  must come back pixel-identical, and the boot budget (355 KB, Lex's decision B) holds by removing at least as much
  as the slice adds.
- **The design board follows.** A part whose component file is done names it (`css` in `src/catalogue/parts.ts`):
  selecting it shows that file in the right panel, editable on the live cell only, with Reset and Send to agent, in
  place of the generic Tweak fields. The live cell draws in a shadow root holding the board's other styles and the
  file as edited, so a deleted rule or a selector naming other parts stays in that cell. Component files are left out
  of other parts' Tweak fields.
- **The one-off count reads hooks as what they stand for.** In a file on the components layer, a hook counts as the
  counted property its name ends in (`scripts/agents/one-offs.mjs`): `--btn-padding-block` as `padding-block`,
  `--btn-icon-gap` as `gap`. A hook that ends in none (`--btn-font-weight`) counts as a local custom property only when
  it holds a hand-typed length, time or percentage. A component's defaults are held to tokens, not hand-typed values.

## Slices, in order

1. **Pilot: the Button** (this PR). The layer order; the bare `button`, `select` and `a` rules on `elements`; the
   Button's whole look in `src/ui/parts/button.css` with `--btn-min-block-size`, `--btn-radius`,
   `--btn-padding-block`, `--btn-padding-inline`, `--btn-background`, `--btn-hover-background`, `--btn-text-color`,
   `--btn-font-size` and `--btn-font-weight`; the board's CSS section for it; the one-off count reading hooks.
2. **Icon button and text button.** `.icon-button`, `.text-button` and `.text-link` out of `src/style.css` into
   their own files, as board parts with their CSS shown.
3. **The atoms that already have a file.** Badge, Keyboard key, Spinner, Progress bar, Section heading and Inline
   field onto `components`, their fixed values turned into `--<name>-*` defaults; the board shows each file.
4. **Tokens.** `src/theme.css` (and the generator's output) on `@layer tokens`.
5. **Elements and the old foundation.** The rest of the bare element rules onto `elements`; `src/utilities.css`
   folded in or removed.
6. **Molecules.** Row menu, dropdown, flyout, sharing row and confirm dialog as component files.
7. **Screen layout.** `src/style.css` split by screen into unlayered editor files; it keeps only the order line
   and its imports. Waits for the top bar work (ticket 66 and the phone layout) to land.

Open for Lex later: the Framework names its variants `data-variant="secondary"` and `data-size="small"`; the editor
keeps its `button secondary` classes for now, as moving every call site is a slice of its own.
