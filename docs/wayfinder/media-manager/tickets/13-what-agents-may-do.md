## Question

Agents may see media, place and swap it, write alt text, and run the same optimise and clean-up the user can, but may not add new files (settled). Which MCP tools does that need (list media with sizes and uses, place or replace an image with the same markup the editor writes, set alt text and the focus point, run optimise, run clean-up or the fix-all), and which of them must Lex confirm before they take effect? How does an agent run optimise when optimising happens in the user's browser: does it queue the job for the next time the editor is open, or does the Worker do it? What do the site conventions and the shipped `AGENTS.md` say about media (one source, per the components-and-builder map's ticket 05)? How does Lex see and review alt text an agent wrote?

## Comments

- 2026-10-13 (facts, Explore subagent on `dev`): today agents have no media tools; `write_file` takes text only and the conventions say "the user uploads other images in the editor" (`worker/site-conventions.ts:41`). Every agent change is queued by the Worker and applied by the open editor tab with the editor's own code, becoming an ordinary unsaved draft with Undo and Discard; only Lex saves (no save tool). There is no lasting queue: a change not picked up within 2 minutes expires, so agents can act only while the editor is open. The browser's Optimise worker exists but no agent operation reaches it. One OAuth scope (`site`), no per-tool permissions. Drafts record no author; only status text says "An agent changed X." The starter's `AGENTS.md` says only that images live in `images/` with root links; no alt, size or format guidance. Alt warning fires only when `alt` is absent; `alt=""` counts as decorative.
- 2026-10-13, Lex: **Framing: shape, focus and trimming.** When an agent places a picture it may pick the spot's shape, move the focus dot, and also trim, zoom, turn or flip, which saves a trimmed copy as a new file (ticket 09). Declined: shape and focus only (recommended; trimming stays with Lex in the Image popup), and no framing at all. Consequence: the "agents add no new files" rule now means no new media from outside the site (no uploading, fetching or generating); copies made from pictures already in the site (trimmed copies) are allowed.
- 2026-10-13, Lex: **No extra confirmation.** Every agent media action, including Clean up (removing files) and Improve images across many pages, arrives as ordinary unsaved changes that Lex checks, undoes or discards before saving; removed files stay restorable for 30 days (ticket 10). Declined: a Yes/No in the editor first for removing files and the fix-all (recommended), and a Yes/No for every media action. Fact behind it: agents act only while the editor is open, so optimising an agent's request simply runs in that open tab; no queue is needed.
- 2026-10-13, Lex: **Used files only after swapping them out.** An agent may remove a media file that is still mentioned only once it has swapped it out of every mention, so no visitor sees a broken picture; files marked Always keep are never removed by an agent. Declined: only unused files (what Clean up offers), and the same as Lex (remove while still used, with a report of pages that break).
- 2026-10-13, Lex: **Always keep: agents may add it, never remove it.** An agent may mark a file Always keep (for example when it finds the file linked from outside), but only Lex can take the mark off. Declined: leave the mark entirely to Lex, and let agents add and remove it.
- 2026-10-13, Lex: **Descriptions per picture, each spot can differ.** A media file's description (alt text) is written once in its details and every new place uses it; a place that needs other words can have its own. Gaps show on the file in Media and on the place. Declined: per place only (written at every place), and per picture only (no place can differ).
- 2026-10-13, Lex: **Empty descriptions count as "not described yet".** Old empty alt text is a gap until someone marks the picture (or place) **Decorative**; techies-reviews would show about 490 gaps at first, which an agent may fill or mark Decorative. Declined: keep empty ones as decoration (only missing alt and new pictures are gaps), and ask once per site.
- 2026-10-13, Lex: **Agent descriptions are marked until Lex checks them.** Each description an agent writes carries a small "by agent" mark, and Media gets a **Descriptions to check** list (picture, text, OK or Edit). Visitors see the text as soon as Lex saves; the mark is only a reminder. Declined: treat them like any other unsaved change with no lasting mark, and suggestions that stay out of the pages until accepted one by one or all at once.
- 2026-10-13, Lex: **Agents may run Improve images, but outside pictures stay with Lex.** An agent may make lighter files with responsive copies for heavy pictures already in the site and turn GIFs into looping video (ticket 11); pictures loaded from other websites are left as they are and listed for Lex to bring in. Declined: let agents bring outside pictures in too (an exception because pages already show them), and keep Improve images to Lex alone (agents only report which pages would benefit).
- 2026-10-13, Lex: **YouTube and Vimeo: only videos already in Media.** Agents may place again a pasted video already listed in Media (its still picture is already in the site). Pasting a new address, and switching old YouTube or Vimeo players to "picture until tapped" in Improve images (both copy a picture in from outside), stay with Lex. Declined: any address (an exception to "no new media from outside"), and never.
- 2026-10-13, Lex: **Agents may write and attach subtitles.** An agent may write a subtitles file (for example from a script Lex gave it) and attach it to a video or audio; like descriptions, it carries the "by agent" mark until Lex checks it. Declined: attach existing subtitles files only (recommended; writing stays with Lex because words or timing may be wrong), and leave subtitles to Lex entirely. Consequence: an agent-written subtitles file is a second allowed kind of new file, besides trimmed copies; it is text the agent writes, not media brought in from outside.
