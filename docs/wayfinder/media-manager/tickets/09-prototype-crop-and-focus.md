## Question

How do crop and the focus point look and behave? The focus point is set in the edit bar for each place an image is used (settled). Mock up (published with `html_render`): setting the focus point on a selected image (a dot to drag, a live preview at phone and desktop widths), and cropping (fixed shapes such as square, 4:3, 16:9, free). Decide with Lex: is crop done in the manager to the file (a new file), or per place in the edit bar like the focus point? Does rotate come with crop? What happens to a crop when the image is replaced? How do they show on images inside components?

## Resolution (2026-10-13)

Lex confirmed the complete plan by choosing **Yes, confirm and close**. Only this planning ticket closes; implementation, pushes and deployments remain unauthorised. Design references: [crop-popup.html](../prototype/crop-popup.html) (selected; everyday image popup plus the large editor) and the large window in [crop-wordpress-style.html](../prototype/crop-wordpress-style.html), with the [Brizy popup](../prototype/references/brizy-image-popup.webp) and real WordPress 7.1 Media Editor screenshots in [references](../prototype/references/README.md). The first three-way comparison, [crop-focus.html](../prototype/crop-focus.html), is historical. Validation notes sit beside each mockup.

**Entry point and popup.** The edit bar has one **Image** button (image icon, where Replace image… was) with a small state badge such as "Square", "Card's shape" or "Trimmed"; there is no separate Crop or Focus point button. It opens a compact Brizy-style **image popup**: the whole picture with the shape menu over it and a draggable focus dot (the frame of what the place shows drawn over it), a Replace link under the picture, Zoom, Turn left/right, small live phone and computer previews, a one-line message, **Open large editor** and **Done**. Nothing is kept until Done; ✕ or Escape cancels everything, including a replacement made in the popup. Done is undoable like other edits. The popup sits beside the picture on wide screens (below the bar when there is no room) and becomes a bottom sheet on phones with 44 px targets. Its colours follow the editor's chosen light or dark look, like the edit bar. Arrow keys move the dot or frame.

**Shapes and what gets saved.** Shapes: Original, Square, 4:3, 16:9, Tall 4:5 and Free. Choosing a shape and placing the focus dot change only that place and save nothing new (per-place `aspect-ratio`, `object-fit: cover` and inline `object-position`, as in ticket 08's research). Free trimming (four corners in the popup), zooming in, turning, straightening and flipping save a **trimmed copy**: a new media file used only by that place, while other places keep the original. A live message always says which of the two will happen: blue "Only changes this spot" or yellow "Saves a new picture for this spot".

**Large editor.** Open large editor opens a WordPress 7.1 Media Editor-style window carrying over the popup's state: picture area with handles and a straighten ruler, a side panel with Turn, Flip, Zoom, Shape, the live message and live previews, Reset/Undo/Redo, Cancel and Done (Cancel returns to the popup as it was). It differs from WordPress on purpose: a shape change alone saves no file, re-cropping starts from the original, there is a focus point, components open on their own shape, and alt text stays in the edit bar rather than a Details tab. On phones it uses WordPress's single icon row and shape menu, with the preview behind a Preview button.

**Trimmed copies.** Named from the original with `-crop` (for example `studio-lights-crop.webp`), numbered on conflict per the adding naming rules, prepared with the site's image recipe and given their own responsive copies; details show "Made from <original>". The original is never changed. The editor remembers the source and trim so re-cropping can start from the original.

**Replacing and re-cropping.** Replacing the picture in a place keeps the place's shape, resets the focus to the middle and drops any trim or turn made for the old picture, with a short note. Re-cropping starts from the full original with the earlier trim restored. On Done the earlier trimmed copy is replaced if no other place uses it; otherwise a new trimmed copy is made so the other place does not change. (Build note: write the new trim under a fresh name and remove the old one rather than overwriting the same address, so cached copies cannot show the old trim.)

**Components, sharing and backgrounds.** When a component gives its picture a fixed shape, the popup opens on that shape, labelled for example "Card's shape (4:3)"; other shapes stay available with a note that this item will look different from the others. A component template's own fallback picture has no image popup. The Social image in settings gets the same Image button and popup fixed to the 1200 × 630 sharing shape, which adjusts the sharing copy from ticket 08. CSS background images get no crop or focus point.

**Scope.** Whether agents may crop belongs to [Decide what agents may do with media](13-what-agents-may-do.md); removing trimmed copies nothing uses belongs to [Decide how unused media is cleaned up safely](10-safe-clean-up.md). Lazy loading and loading priority stay automatic (ticket 08), so the popup has no such switches. Not validated: Safari, real touch, swipe-to-close and pinch zoom. No editor implementation, push or deployment is authorised.
