## What

Research [02](../../tickets/02-research-optimising-every-media-kind.md#resolution-2026-10-11) §3–4, ticket [07](../../tickets/07-one-upload-path.md#resolution-2026-10-13).

- **HEIC/HEIF**: Safari 17+ decodes natively; other browsers load a decoder (libheif, about 480 KB) only when a HEIC file arrives. An undecodable HEIC is never presented as a usable website image. Before shipping, record the decoder's licence and the HEVC patent question in the Done section and stop for the lead if unclear.
- **SVG** stays SVG: minified, artwork kept, scripts and other executable content removed; needs no raster copies; placed with `width`/`height`.
- **PNG** that stays PNG gets a lossless squeeze (oxipng, on demand).
- The file chooser accepts `.heic,.heif` everywhere.

## Done (2026-10-14)

- **Behaviour.** All new code is in lazily loaded chunks reached only from the optimise worker (`media-codecs.ts` is the one seam for every codec).
  - **SVG stays SVG** (`media-svg.ts`, SVGO 4.1 browser build, on demand). An SVG without a stylesheet is minified with SVGO's `preset-default` (multipass, ids kept). Executable content is always removed: `<script>`, every `on…` attribute, `javascript:`/`vbscript:`/`data:text/html` links in link attributes (any case, spacing or entity spelling), `foreignObject`, `iframe`, `embed`, `object`, `animate`/`set` that retarget a link or handler, and `<?xml-stylesheet?>` (XSLT). A stylesheet can select by any detail (names, order, emptiness, whitespace, attribute values), so a **styled SVG with nothing executable keeps its exact bytes**, and a styled one with executable content loses only that, its comments and its DOCTYPE. No raster copies; `width`/`height` read from the attributes or `viewBox` reach placement. Keep original cannot skip the clean-up.
  - **Safety check** (`svgHasExecutableContent` in `media-limits.ts`, used after cleaning and by slice 30's unchanged-file fallback) is now a small XML scanner: elements and quoted attributes, processing instructions and DOCTYPE; displayed text, CDATA and comments are skipped, so words like "online=yes" stay. Unreadable markup, DOCTYPE entity definitions and unknown entities count as unsafe, so such a file is refused with the scripts advice and never offered unchanged.
  - **PNG that stays PNG** (main and copies, including a stripped-source main) gets a lossless oxipng squeeze (`media-png.ts`, single-thread `@jsquash/oxipng` WASM, level 2, alpha untouched), kept only when smaller; copies pass the "smaller than the main" gate after squeezing; a failure keeps the PNG. Animated PNGs are never squeezed.
  - **HEIC/HEIF** is always prepared to the image recipe (WebP etc.; `mediaNeedsPreparation`, pending names predict `.webp`; extensionless files by their first 4 KB). The browser's own decoder goes first (Safari 17+); only a HEIC it cannot open reaches `loadHeicDecoder`. **On dev that seam reports "not available"** (see the decoder below), so Chrome and Firefox give the advice "photo.heic could not be prepared. This browser cannot open HEIC photos. Save it as JPEG and add it again." A HEIC is never offered unchanged, not even with Keep original. HEIC never reuses source bytes, so no camera or location data passes.
  - **File choosers.** The Media pane and picker input already accepts `image/*,.heic,.heif`; Files → Upload files… accepts everything; the edit bar's optional upload control has no callers.
  - **Build.** Workers build as ES modules (`worker.format: "es"`) so codecs split into chunks; the codecs are prebundled for the dev server (it otherwise re-optimised them mid-session and reloaded, duplicating editor modules). CSP already allows WASM (`'wasm-unsafe-eval'`); the oxipng WASM loads under it in the browser spec.

  - **Licence:** libheif-js is **LGPL-3.0** (libheif and libde265 inside). That is not a permissive licence like MIT. Using it from the MIT editor is generally fine when it ships as a separate, replaceable module with its licence text and source available. The WASM is a separate asset, but no licence notice ships with the build yet.
  - **Patents:** the decoder (libde265) decodes HEVC, which is patent-pooled. HEVC Advance said in 2016 it would not seek royalties for decoders that users download and run in software on a general CPU, such as a browser. Other holders, such as the Via LA pool and independent patent owners, are not covered, and whether that waiver still applies today was not confirmed. Research 02 left this for Lex.
