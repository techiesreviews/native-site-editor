## Done (2026-10-14)

- **Behaviour.** The Choose image modal is now the **Media picker** (ticket 06, tiles.html): the Media pane's view in a smaller window (960 px wide, full-screen under 580 px). A compact header names the place ("Home · <the image's words>", "Site settings · Favicon", "Media card · Image") with Close. The One bar has Search, Collections (with Manage collections…) and More (Add new file, Grid/List, Rename/Delete collection while viewing one; no kinds, since only files that fit the place show). A tile **chooses** its file ("Choose <path>", pressed; ring and check); there is no multi-select. The chosen file's picture and name, with **File details**, sit above (phones) or beside one row of **Cancel** and **Use image** (44 px; Use waits for a choice). File details, collection screens and adding work inside it with their own action rows; Back keeps the choice. Cancel, Close and Escape keep the existing placement, even when pressed while Use is still reading. Adding inside the picker (More → Add new file, drop on the picker, or a file dropped on a page's image) uses slice 17's drop-to-add path, with no Optimise screen first. It chooses the new file and never places it without Use (lead follow-up 1). Every entry uses it: the Edit bar's and Structure's Choose image…, canvas double-click and drop, Structure's slot image card and the component panel's image field (**Choose image…**, was Upload image…), and Site settings (**Choose favicon… / social image… / default image…**, were Upload …). Placing still writes today's markup.
- **Use and descriptions (lead follow-up 2, ★).** The insertion alt field is gone; Use decides the alt from the records (`swapPlaceImage`, `media-descriptions.ts`). A place's own words stay. A place that followed the old file (its description, or no alt) follows the new file: its description, `alt=""` for a Decorative file, else the name fallback. An empty, unmarked alt stays a gap unless the new file is described. A place's **Decorative** mark moves to the new file on that page (`files[new].places[page].decorative`). It leaves the old file only when that file no longer shows on the page. The page and records change in one batch, so one Undo brings both back. Unreadable records never block a swap and are then not written; a newer records draft refuses it like a newer page.
- **Assumptions.** Details open from File details beside the chosen file (or the usage window), as the prototype's tiles only choose. Structure's slot session no longer closes on a Structure redraw (the picker outlives it; the session's own instance checks refuse a stale choice). Uploads in the picker follow the stored Optimise defaults (byte-exact only for SVGs, as in the pane).
