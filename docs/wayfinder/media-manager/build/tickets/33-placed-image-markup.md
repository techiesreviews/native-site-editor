## What

Ticket [08](../../tickets/08-responsive-image-output.md#resolution-2026-10-13) "Everyday page markup", "Size hint", "Loading order"; `src/page-builder/media-markup.ts`.

- Plain `<img>` with `srcset` (copies smaller than the main image plus the main at its real width; never the original) and measured `sizes`; `width`/`height` from the file used. Replaces the `960px` default.
- Lazy images get `loading="lazy"` and `auto, ` before the measured list. Images whose top is on the first screen at phone or desktop width load straight away, without `auto`; the first large one gets `fetchpriority="high"`.
- Re-checked when an image is placed, replaced or moved. No switch in the edit bar.
- Images in component slots get the same markup; a component template's own fallback is left alone.
- The preview's asset scanner (`referencedAssets`, `src/main.ts:2319`) uses the shared scanner, so `srcset` copies load in the canvas.

## Done (2026-10-14)

- **Behaviour.** Placing or replacing an image (the picker's Use, agent `place_media`, and the component slot pickers in Structure and the component panel) now writes a plain `<img>`: `srcset` lists the copies smaller than the main image, ascending, then the main at its real width (never `media/originals/`); no copies (SVG, small images) means no `srcset`/`sizes`; `width`/`height` always come from the file used (removed when unknown); `decoding="async"`; classes, slots, styles and other attributes are kept. `sizes` is measured: before writing, the preview's hidden copy lays the place out with the new file's size standing in (`measure-image` request `image`), so the change stays one Undo step. First-screen images (top on the first screen at 390 × 844 or 1280 × 800) have no `loading` and no `auto`; the first large first-screen image of the page (document order) gets `fetchpriority="high"`, and every other measured page image loses it in the same step (a new holder also becomes eager). Other images get `loading="lazy"` and `auto, ` before the measured list. Placed images elsewhere on the page (those with `sizes`) follow their own first-screen fact, since a new size can move them across the fold; hand-written images change only for the priority holder. When nothing can be measured (the preview shows another page, a timeout), the image is lazy with `sizes="auto, 100vw"`; placing never waits on a failed measurement. The `960px` default is gone.
- **Component slots.** A slot image on a page gets the same markup. A first fill (no page image yet) is measured on the instance's fallback image in that slot (request `slot`), with that slot and its wrappers shown in the copy when the preview hides them, and the measured page list shifted past the new fill. A component template's own fallback is never rewritten. Typed slot addresses, card fill and card swap keep their markup (no file is placed there).
- **Canvas.** `referencedAssets` is gone: `loadNativeAssets` uses the shared scanner (`scanMediaReferences`, dynamic import, so boot stays flat), so `srcset` copies and `<source>` files load; the frame runtime rewrites `srcset` candidates to the loaded data URLs. Pre-paint font loading keeps its CSS-only reader.
- **Assumptions (★).** "Large" (not defined by the plan) is a rendered border box of at least 50,000 CSS px² with its top on the first screen at 390 or 1280 px, the threshold WordPress uses for the same decision. The measured page list is capped at 1,000 images and node paths at 40 steps.
- **Not done: the re-check after a move.** Moving a block does not re-measure its images. Writing that re-check into the move's Undo step needs a typing-style group the re-check can join, but the draft store merges any grouped write on the same file into an open group (`draft-store.ts` `edit`, `last.group && last.key === key`), so a component-field keystroke during the measurement could join the move. A separate Undo step after a move was ruled out. See the lead's decision below.
