## What

Ticket [11](../../tickets/11-fix-all-existing-images.md#resolution-2026-10-13) "Where and how"; Wix's step-by-step fixer from research [01](../../tickets/01-research-mobbin-patterns.md#resolution-2026-10-11).

- **Improve images** in Media's More, next to Clean up. Runs only when Lex presses it.
- Rows for pages and components with their reach and what would change; a row opens to show its pictures; any picture can be unticked (remembered).
- Fix one row or **Fix all** (components included). Progress with Cancel; finished rows stay done; closing the editor stops the run with the rest still listed.
- After a run, a list of changed pages and components with **Undo** each and **Undo all**. Nothing goes live until saved.
- The Media tab badge also counts this work.

## Done (2026-10-15)

- **Behaviour.** Media → More → **Improve images** sits after Clean up. It is always openable and shows the count once the use check has counted ("Improve images (2)"). It opens its own screen with Back, like slice 50's Clean up (lazy `src/page-builder/media-library-improve.ts`, `media-improve.css`, rules in `improve-images-words.ts`).
  - **The list.** First "Checking the pictures on your pages…", then "Reading pictures: n of N" while the widths the listing lacks are read from the bytes (slice 70's `missingFacts`). Then one line of what it does, and one card per page and component, components first with their reach ("On 97 pages · 1 GIF"). Each card says what would change, has its own **Fix**, and a footer gives "N to improve" with **Fix all** (components included). With nothing left it says "Every picture is in good shape."
  - **An opened row** lists its pictures: thumbnail (own files from the library's bytes, outside ones from their website, players as a sign), the name, what happens in plain words ("Heavy: a lighter file", "From another website: keep a copy here", "GIF: becomes a looping video", "Shows a picture until tapped", "Add size details"), and a tick. Unticking writes `leftAsIs` for that row in `.editor/media.json`, so it is remembered. Ticking again also lifts an "everywhere" entry. A muted line counts the pictures left alone (scripts, sample code, structured data).
  - **Running.** "Improving 2 of 5: Home" with **Cancel**, as the pane's one cancellable task (other controls wait). Each page row is first shown in the canvas (new `showPage` port: opens it, waits up to 5 s until it is drawn), so pictures get the preview's first-screen measurement (slice 33): brought-in pictures below the fold become lazy and heavy ones get measured `sizes` (slice 71 and 72 follow-ups). Component templates are not measured (the preview measures page nodes only) and use the engines' safe fallback. Finished rows stay done ("Done", "Nothing to change", "Not changed: …", plus any engine notes). Cancel, or closing Media or the editor, stops with nothing half-saved and the rest still listed. The run's abort is the sheet's work, which view disposal aborts.
  - **One save per row (lead).** New `src/page-builder/improve-images-run.ts`: `stagingContext` gives the three engines (71 outside pictures, 72 heavy files, 73 GIFs and players) a workspace whose saves are collected instead of made. Each engine reads what the one before prepared, and the row is saved once, labelled "Improve images: <row>": one Undo step per page or component. The merged save proves the real site (first-seen sources and versions, the real path list, no proofs for staged files). Run memory (outside reads, brought-in pictures, converted GIFs, player stills) is reused across rows, forgets what an Undo removed, and drops a row's additions if its save fails. An outside GIF is judged again after it arrives, so it loops in the same save. `siteUrl` (the address from Site settings) goes to the heavy engine for slice 95's sharing copies and to the GIF and outside engines.
  - **Pictures from other websites.** One that cannot be brought in shows **website gone** or **not allowed** on its row, with **Use my own copy** (a file chooser). Lex's copy is used at once by running that row again (slice 71's `own`).
  - **Undo.** After a run, a **Changed** box lists each changed page or component with **Undo**, plus **Undo all** when there are several, and "Nothing goes live until you publish." `undoRows` is a forward change, so it works in any order and is itself undoable. Page text goes back if unchanged since, and is otherwise refused with the file named. Records go back field by field (`revertJson`: a field changed since keeps its newer value). Added files (lighter files, copies, brought-in pictures, looping videos, the player) are removed once nothing mentions them: a file a later row still uses stays with its record and is checked again at the next Undo. Undo proves every page it read (sources) and every SVG (versions).
  - **The Media tab's count** (slice 49) now also counts the pages and components with pictures to improve. The clean-up controller (usage chunk) runs `improveImagesPlan` after each use check, using listing sizes and the widths the screen has read. Clean up publishes first and never waits for it. Dismiss also remembers the rows (`improve:<file>`), and a new row brings the count back. The description reads "1 file to clean up and 2 pages with pictures to improve".
