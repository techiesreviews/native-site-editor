# 11 · What insert, drag and move support today

Research for [ticket 11](../tickets/11-research-insert-drag-today.md). Read against `origin/dev` at `bacb984` (2026-10-08). No product code changed.

## Summary

- **The source layer is ready for nesting. The UI and runtime are not.** `nativeMarkupInsertEdit` and `nativeMoveEdit` (`src/page-builder/native-operations.ts`) already insert into, and move across, any valid HTML container (div, section, article, li…). They check content rules and return one guarded range edit. I checked this with a probe: an img goes into a div inside a section, an h2 moves out of a div, and an `a.btn` moves into a div.
- **Drop targets only exist between sections.** The runtime reports gaps only in containers that already hold a `<section>` or a section component, plus one gap at the end of a `<main>` that has no sections. There are no gaps inside a section or div, and none run sideways in a row or grid.
- **The Add panel offers sections only.** The native Heading, Text, Image, Link button… choices were removed from Add on 2026-10-03 (`ae910d8`, "Offer sections only"). Their code is still there but unwired, and `docs/page-builder/elements.md` still describes them as shipped.
- **Moving by drag works for whole sections only, and only among their siblings.** This is true on the canvas (edit-bar grip) and in Structure. Alt+↑/↓ in Structure moves any element, but only among its siblings. The tested "Move to… container" helper (`nativeElementMoveChoices`) is not wired to anything.
- **Each step is one undo step.** Every insert or move is one `replaceActiveRanges` call. Plain sections that bring CSS use a multi-file history receipt. The builder needs nothing new here.
- **Components are closed to drops.** Source operations treat every custom element as a sealed box. Nothing can be inserted into, moved into or moved out of an instance's light DOM, which is where its slots are filled. Only components whose template is a single `<section>` can be added at all, and only between sections.

## What exists today

| Area | Supports | Limits |
|---|---|---|
| Insert points (runtime) | Gaps between the children of any element holding a section-like child; end of a section-less `<main>`; empty-`<main>` area | No gaps inside a section or div; horizontal lines only; nothing in master/template sessions |
| Add panel click | After the selected section (or the instance around a selected template element), else end of `<main>` | Section components and saved plain sections only |
| Add panel drag | Pointer captured on the item, nearest gap by `pointAt`, auto-scroll, Esc and release-off-canvas cancel, refusal message | Same section gaps; drop label says "Drop section here" |
| Plus buttons | Keyboard-focusable, open the panel for one gap | Section gaps only |
| Canvas move | Edit-bar grip drag, Move up/down buttons, Alt+↑/↓, ↑/↓ on the grip | Sections only, same parent only, y-axis only |
| Structure move | Row drag (sections), Alt+↑/↓ (any element) | Siblings only; a parent with one child refuses; no nest or un-nest |
| Source ops | Insert/move into any valid container, cross-parent moves, path of the moved element after the move | Custom elements, SVG, template and noscript are sealed |
| Undo | One step per insert, move, duplicate or remove | — |

## Gaps the builder must close

Size: **S** ≈ under a day, **M** ≈ 1–3 days, **L** ≈ more than 3 days or a design decision first.

1. **No drop targets inside sections or divs (L).** `insertPoints()` skips any container without a section-like child at `src/components/native-preview-runtime.js:772` (whole function: 766–813, plus `sectionlessMain` at 823). The builder needs pointer-driven targets: find the deepest container under the pointer, report the gaps among its children and the gaps just before and after it, and check each one against the dragged block with `nativeMarkupInsertEdit` or `nativeMoveEdit` before showing it. These should be computed per drag move rather than reporting every gap on the page, both for speed and to keep the screen readable.
2. **Gaps only run one way (M).** Gaps are horizontal lines placed at midpoints between children. `pointAt` scores by y first (`src/page-builder/insert-target.ts:192-207`). The runtime's `dragGap` uses only y midpoints (`native-preview-runtime.js:2395-2402`), and `dragMessage` reads only `msg.y` (2470-2471). Rows, grids and columns (button rows, card grids) need gaps along the x-axis with vertical indicator lines, so the editor must send x to the runtime as well.
3. **Drop indicator says "section" and shows no container (S–M).** "Drop section here" is hard-coded (`src/components/insert-controls.ts:63`, `:138`). While dragging, only the gaps of the target's parent are shown (`:151-153`). A builder needs a block-neutral label, an outline of the target container ("Into Div"), and a depth cue for nested gaps.
4. **The block catalogue is not wired, and part of it is missing (S–M).** Add lists only components whose template is a `<section>` (`src/main.ts:2332-2341`, filter at `:2338`) plus saved plain sections (`main.ts:452`). `nativeElementChoices` (`src/page-builder/native-elements.ts:38-45`) was unwired in `ae910d8`. It has no Section, Div or Span, and `link-button` writes an `<a>` without a class, while the map wants the site's button class. Grid and Columns are still refused (`main.ts:2352`). Doc drift: `docs/page-builder/elements.md` ("Integrated Add catalogue") and `add-panel.md` ("Known gaps") still say native elements share the catalogue.
5. **A dropped element ignores where the pointer is (S, once gap 1 exists).** `nativeElementAddPoint` builds no container candidates unless the mode is `"click"` (`main.ts:2361`). A drop therefore falls back to the section gap. With pointer-driven targets, a drop should take the nested gap directly.
6. **Canvas drag moves only sections, only among siblings (M–L).** The edit-bar grip is enabled only for section tags (`main.ts:1979-1980`). The runtime's `startSectionDrag` requires `sectionLike(selected)` and stays in `selected.parentElement` (`native-preview-runtime.js:2443-2466`). `moveNativeSectionTo` refuses another parent (`main.ts:2193`). The builder needs a grip on any block and a cross-container drop using the targets from gap 1, with `nativeMoveEdit` doing the write. `nativeElementMovePlan` already returns the path to select afterwards.
7. **Two move engines (S–M).** Sections move with `moveEdit`/`swapEdits` (`src/native-structure.ts:83`, `:101`; called at `main.ts:2202`). Elements move with `nativeMoveEdit` (`native-operations.ts:336`), which has the content-rule guards. The builder should use `nativeMoveEdit`/`nativeElementMovePlan` for everything, so sections and blocks follow one rule set.
8. **Structure tree: no nesting by drag (M).** Only sections can be dragged (`main.ts:535`). A drag stays among the pressed row's siblings and refuses a parent with one child (`src/components/page-structure.ts:380-393`; gap finding at `:320-328`). The builder needs a drop onto a row (inside), drops before and after rows at other depths, and a horizontal offset to choose the depth, all checked by `nativeMoveEdit`.
9. **Keyboard alternatives stop at siblings (M).** Alt+↑/↓ in Structure moves any element (`main.ts:529`, `page-structure.ts:815-820`). On the canvas it reaches only sections, because the edit bar's `onMove` is set only for them (`main.ts:1980`, `:2026`). Canvas Ctrl/⌘+D and Delete are also sections only (`native-preview-runtime.js:2212-2213`). Missing: keys for "into the previous sibling" and "out to the parent" (indent and outdent), and a Move to… picker. `nativeElementMoveChoices` (`src/page-builder/native-move-choices.ts:99-114`) is a tested, unwired base for that picker. Inserting by keyboard works: the Add panel has arrows, Enter and Esc, and Enter inserts at the default point.
10. **Undo granularity: no gap (S, only for checking).** `replaceActiveRanges` makes one range edit per insert or move (`src/components/source-editor.ts:497-503`). `tests/native-save/native-add-panel.spec.ts` already checks one undo step for a drop. If a block ever brings CSS with it, it must go through `prepareHistorySources` like plain sections (`docs/page-builder/history-actions.md`).
11. **Components block nesting (L, needs a decision).** In source operations, custom elements are sealed: `native-operations.ts:112` sets `opaque`, `atPath` stops at sealed nodes (`:147`), and `validFragment` refuses any `-` name (`:256`). Probe results: inserting `<p slot="body">` into `<card-note>` is refused, moving `<h3 slot="title">` out is refused, moving the instance into a div is refused, and inserting `<card-note>` with `nativeMarkupInsertEdit` is refused. Component instances go in only through `nativeInsertEdit` (`src/native-insert.ts:381`), between sections. Under the settled rule that a slot wraps the whole element, dropping into an instance would mean writing a `slot="name"` element as a light-DOM child. A decision is needed: refuse drops into instances, or offer the instance's named slots as targets. Non-section components (a button or card component) cannot be added anywhere today.
12. **No inserts inside a template or master (L, already listed under "Not yet specified").** In a master session `insertPoints()` returns nothing (`native-preview-runtime.js:769`). Selecting inside a shadow tree maps the Add target to the host instance (`pageNode`, `:1886-1892`). Building inside a component template is not possible today.
13. **Cards cannot be reordered by drag (M; listed under "Not yet specified").** `docs/page-builder/cards.md:164` says only Move and Alt+↑/↓ work. This becomes a case of gaps 2 and 6, a sideways drag inside a grid.
14. **Touch has not been tested (S).** Add items use `touch-action: pan-y` (`src/page-builder/add-panel.css:141`), so a vertical touch drag scrolls the list instead of dragging. Drag has only been tried with a mouse (`add-panel.md` Known gaps).
15. **Possible inconsistency (S).** `insertPoints()` walks the instances' light DOM (`pageEl.querySelectorAll("*")`, `:769`). If a `<section>` sits in an instance's light DOM, it would get gaps that `nativeInsertEdit`, which has no sealed-node check, could write into. This is not reachable with today's starter. Gap 1's targets should apply the same sealed boundary as `native-operations.ts`.

## Reuse for the builder

- `nativeDestinations` / `nativeMarkupInsertEdit` / `nativeMoveEdit` / `nativeElementMovePlan`: the source contract for before, after and inside, with one guarded edit and the path to select afterwards.
- `makeInsertDraggable` (`insert-drag.ts`): drag start threshold, pointer capture, ghost, auto-scroll, Esc and announcements. It stays the same for blocks; only `pointAt` and `target` change.
- The edit-bar grip's drag protocol (`drag-start/move/end/cancel`, runtime-owned geometry) can carry block moves once x is sent and targets are nested.
