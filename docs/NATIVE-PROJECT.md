## Current Slice

Working:

- Browser-native preview for `.astro-editor/native.json`: persistent sandboxed iframe, HTML/CSS/component patching, shared styles, native slots, nested shadow DOM components, route-preserving source updates, and no Astro build per edit.
- Native preview click-to-select: a plain click on any preview element selects it immediately and opens the owning page/component source plus rendered matching CSS rules from the current document or shadow tree without reloading the frame. The owning file opens with the caret just after the element's start tag, which stays highlighted while the file is edited; the runtime reports element-child indexes and `src/native-source-location.ts` maps them to source offsets through the same browser parser. There is no mode button. Ctrl/⌘+click follows a `#route` link. The preview has no toolbar; the frame fills the pane above the code split.
- Edit bar: selecting an element in the native preview shows a contextual toolbar (`src/components/edit-bar.ts`) anchored to it inside the preview pane: 8 px above the selection when that fits, below it otherwise, else pinned to the frame top; it follows scroll and resize through `selection-rect` messages from the runtime and hides while the element is out of view or another file opens over the page. It does not appear for the page's `main` container. It starts with a kind label (Heading, Paragraph, Link, Section, or the tag for components), then: **Heading level** (H1–H6, renames both tags), **Text size** (not for `section`, `header`, `footer`, `nav`, `article`, `aside` or components; Default, XS–4XL as an inline `font-size` in rem on the element's start tag; an unlisted inline size shows as Custom; Default removes the declaration and an emptied `style` attribute), **B** and **I** (with text selected inside the element, wrap exactly that range in `<strong>`/`<em>`, or remove the enclosing `strong`/`em` (`b`/`i` too) when the selection already sits in one; with no text selected, the element's whole content is wrapped or unwrapped; Ctrl/⌘+B and Ctrl/⌘+I work inside the preview and with focus in the bar). The runtime reports the selection as offsets into the element's text content plus its enclosing inline wrappers; `textRangeInSource` maps those offsets to inner-source offsets, skipping tags and comments and decoding entities, verifies the decoded slice equals the selected text, and refuses a span that cuts through a tag (the bar then says to select text within one element). After the edit the runtime re-selects the same text so a second format applies to the same word, and **Follow link** (for `#route` links, also when the selection sits inside one). Element ranges come from `locateNativeElementRange` in `src/native-source-location.ts`, which resolves the exact outer range (end tag found before the next non-descendant start tag; same-name descendants counted) and fails closed on implied end tags or stray markup, in which case only Follow link remains. Each action is one verified range edit and one undo step through the existing visual history; Ctrl/⌘+Z and Ctrl+Y with focus on a bar button run the same document shortcut as the rest of the editor. The runtime remembers the selected element's index path before each render and re-selects that position when the element was replaced (renamed heading, undo), and the host can request another position through `selectNode` in the update payload. The runtime reconciler pairs keyed nodes in order, so two elements sharing a `data-key` render as separate nodes.
- Typing in the preview: a text element whose content is only text and inline formatting (`strong`, `em`, `a`, `span`, `br`…) becomes `contenteditable="plaintext-only"` on the press that selects it, so the caret lands where it was clicked. Enter, blur, a click on another element, and Ctrl/⌘+B/I (before formatting) send the element's text before and after as a `text-edit` message; `applyNativeTextEdit` in `src/main.ts` replaces only the changed stretch (common prefix and suffix trimmed; a pure insertion takes one neighbouring character along) through `textRangeInSource`, escaping `&`, `<`, `>` and turning no-break spaces into spaces, as one range edit and one undo step. Formatting around the change stays. A change that crosses a tag is dropped with an error and the preview re-renders from source. Escape drops typing since the last commit. Renders while typing keep the typed text; clicks inside the element move the caret and keep it selected. It waits for the element's file to finish opening when the click is still loading it.
- Edit bar structure, images and accessibility (`src/native-structure.ts`, unit-tested in `tests/native-structure.test.ts`; browser tests in `tests/native-save/native-structure.spec.ts`): a selected whole section (a `section` or a section component with an exact range; nothing else) ends with four icon buttons always visible in the bar (`button` controls with `icon`, the label as `aria-label` and tooltip; the More menu went on 2026-09-24): **Move up**/**Move down** (disabled at the ends; the two sibling ranges swap, whitespace between stays), **Duplicate** (a copy on its own lines after the element, root `data-key` made unique with `uniqueDataKey`) and **Remove** (the element's own lines; the previous sibling is selected next). Icons are stroke paths on a 16 px grid in `edit-bar.ts` (`iconPaths`: link, up, down, duplicate, remove). Each is one range edit and one undo step. An `img` gets **Address** (the live `address` control described under Link address, suggesting every image blob in the branch snapshot, `isImagePath`, the current one marked; "No image" when `src` is empty; Replace and the Apply-style field were merged into it on 2026-09-24) and **Alt text** (the same live control without icon or suggestions: applies as typed, Enter or Escape or focus loss closes, one undo step per opening; the `field` control with Apply, Decorative and hints is gone as of 2026-09-24). Alt text is automated where it can be: with no `alt` attribute the button reads **⚠ Alt text missing** and opening the field writes the file name at once (`initial`, `altFromPath`: `studio-desk@2x.jpg` → "Studio desk"), typing then replaces it; replacing the image rewrites an alt that was never written or still equals the previous file's name, and keeps a written or empty (decorative) one; an emptied field writes `alt=""` (decorative). Links and buttons with no text and no `aria-label` get **⚠ Needs a name** (writes `aria-label` as typed, removed again when emptied); `section`/`nav`/`aside` get **Label** (`aria-label`, likewise), warning **No heading or label** when neither is present; a heading whose level skips the one before it in the same file (`previousHeadingLevel`) gets a one-press **⚠ Use Hn** fix. New attributes go last in the start tag (`setAttributeEdit`, quoting bare attributes and escaping `&`/`"`). Images render in the sandboxed frame: the host finds every relative `<img src>` in the sources (`referencedImages`), reads each blob once through the new `GET /api/raw?repo&sha` (base64, 2 MB limit, `GitHub.raw`) and sends `assets` (path → data URL) with each update; the runtime swaps `src` on render (`resolveAssets`, also for `/path` and `./path`). Uploading a new image file is not supported yet (drafts and publish are text-only), so Address offers files already in the repository or a web address. It opens one text field (`role="combobox"`) prefilled with the `href`, with a listbox of the manifest's routes under it (page title from `native.json` when written, `#/route/` otherwise; the one equal to the field is marked). All pages show until the text changes; then the list narrows to pages whose label or `#/route/` contains the typed text, and disappears when none does, in which case the text itself is the address. There is no Apply: every keystroke rewrites the `href` on the link's start tag from the source as it is at that moment (the link found again by its index path), through `replaceActiveRange` with grouping, so one opening of the field is one undo step, closed when the field closes. Active states in the bar (pressed format, open address, marked item) use `--edit-bar-active`/`--edit-bar-on-active` in `edit-bar.css`: the action colour with its text colour, and in dark scheme the light primary on the darkest, since the app's `--selected` on `--primary` text was unreadable on the dark toolbar (2026-09-24). Picking a page (click, or Down into the list and Enter) writes `#/route/` and closes; Enter in the field closes, taking the one page left when exactly one matches; Escape and focus loss close. The field stays open and focused while the bar re-renders after each keystroke (the re-render carries the new control's handlers over to it). The Page menu and Follow link are gone (2026-09-24); Ctrl/⌘+click in the preview still follows a page link, and `canFollow`/`follow` stay on the preview handle for the runtime's `route` message.
- Conditional template parts (`shared/native-conditionals.ts` for the exporter, `applyEmptyRules` in the runtime; unit tests in `tests/native-conditionals.test.ts`, browser tests in `tests/native-save/native-conditional.spec.ts`): a template element shows only when its slots have content. Automatically: an element that holds one or more `<slot>`s, none of which the page assigned real content (an element or non-blank text) or the template gave a fallback, and that has no text of its own, is hidden, and so is a wrapper whose children are all such elements, so a second button whose slot the page left empty, or the whole actions row when both are empty, does not show. Explicitly: `data-if="name other"` on any template element hides it unless the page assigned every named slot (fallback does not count). The runtime marks hidden elements `data-native-empty` and adopts a constructed sheet `[data-native-empty]{display:none !important}` in every shadow root, recomputed on each render and on `slotchange`, so index paths to the source stay intact; the exporter leaves such elements out of the declarative shadow DOM (`pruneEmptyTemplate`, with `assignedSlotNames` reading the instance's top-level `slot` attributes and default-slot text), using its own stack-based element ranges since `elementEnd` needs the right boundary. In the component-alone preview nothing is assigned, so optional parts are hidden there. The string-level parsing (`startTags`, `elementEnd`, `startTagAttribute`, `textRangeInSource`…) moved to `shared/html-source.ts`, DOM-free so the Worker and Node builds compile it; `src/native-source-location.ts` re-exports it and keeps the DOM-based selection mapping. The fixture's `project-card` gained `<p class="project-card__actions"><slot name="link"></slot></p>`, hidden on every card until a page passes `slot="link"`.
- Insert between sections: any page element (or the page root) whose children include a `<section>` or a section component gets a round plus button over each gap between its children, plus before the first and after the last (`src/components/insert-controls.ts`), centred over the neighbouring items and drawn as an SVG so it sits in the middle of its circle. Only the two around the item under the pointer show (the runtime reports it as `section-hover`, crossing shadow roots); the rest are transparent and ignore the pointer but still show on keyboard focus, and the pair stays while the pointer moves onto a plus. The runtime reports these gaps as `insert-points` messages (parent index path, child index, frame-viewport geometry, and the label of the item that follows) after each render, scroll, resize or page resize; plus buttons scrolled out of the frame are hidden. A plus opens the **Add to the page** picker: its position (`Goes before “…”` or `Goes at the end`), search by name or tag, Down/Up/Home/End, typing on an option to keep searching, Enter with one match, Escape back to the plus, outside click or focus loss to close. It lists only components that fit a section slot: those whose template is exactly one `<section>` element (`isSectionTemplate` in `src/native-insert.ts`, read from the current source so drafts count). A button (`<a>` root) or card (`<article>` root) is never offered; with no fitting component the picker explains the rule instead. Choosing one writes `<tag data-key="tag">` (`tag-2`… when taken) on its own line with the neighbour's indentation, with a `<span slot="…">` child for each named slot in the template whose fallback is text and inline markup, holding a copy of that fallback (`slotMarkup`/`instanceMarkup` in `src/native-insert.ts`), so typing into the new instance's text in the preview changes that page alone and the shared template stays as it is; slots whose fallback is block content (an item list) or that are unnamed stay with the template, as one range edit and one undo step, opens the page file first when a component file is in the editor, selects the new instance and scrolls it into view. When neither neighbour's exact source range can be told, nothing is inserted and an error says so.
- Shared styles in the runtime: each manifest stylesheet is one constructed `CSSStyleSheet` per document (`replaceSync` on change), adopted through `adoptedStyleSheets` by the document and by every component shadow root, so tokens declared in `:root` live once at document level and inherit everywhere and no shadow root holds a copy as a `<style>` element (changed 2026-09-24; before, the full shared stylesheets were injected into every shadow root). `matchingRules` walks a root's own `<style>` sheets and then its adopted sheets, mapping constructed sheets to their source path through a `WeakMap`; the editor's rule ranking is unchanged because cascade order is unchanged. The source and the DOM now have the same element children, so index paths need no style skipping.
- Component CSS: each component lives in `src/components/<name>/<name>.html` and may have a same-named `<name>.css` beside it. It is not listed in `native.json`. The runtime reports which component tags are connected and lack CSS; the editor then looks the sibling file up in the branch snapshot, fetches it on demand, and sends it back so the runtime keeps one constructed sheet per tag and adopts it after the shared sheets in only that component's shadow roots (not the document, not other components). Component CSS drafts render live, are included in Save to GitHub, and their matching rules open as chips or in the secondary editor. At equal specificity the component stylesheet wins the cascade and is ranked as the winner in the editor.
- Explorer: clicking a folder only opens or closes it in the tree; the open file, the preview and the secondary pane stay as they are (the folder summary shows only before any file is open). Opening a component template from the explorer puts its same-named `.css` in the secondary pane (`openComponentLinkedStyle`), or the shared stylesheet when it has none; a page opens beside the shared stylesheet as before. The preview stays visible over any file in a native project. With a component template open, the preview shows the page already on show when it uses that component (directly or inside another component's template, `routeUsesTag`), else the first route that does, else the component by itself on the pseudo-route `/__component__/<tag>/` (`component` in the preview's `update` input): a page of one instance inside a copy of the home page's `<main …>` start tag (`pageContainer`; `<main class="page">` when the home page has none) so the component gets the page's width, belonging to no file, so only clicks inside the component select anything and typing edits the template's slot fallback text. Opening a page brings its route back. In the runtime a `<slot>` is never the selected element (its parent is), and an element whose slot shows the page's own text is not typed into from the template side.
- Existing Monaco editor, explorer, scoped local drafts, Undo/Redo, conflicts, and optimistic Worker Git commit path reused.
- Native save UI is explicit **Save to GitHub**. It commits selected files through `/api/publish`, shows a commit link, and says deployment status is not tracked by this editor. A connected host may deploy the commit automatically. Under each file the panel lists what the commit would change (`src/text-diff.ts`: an LCS line diff of the clean baseline against the draft, shown as hunks with one line of context, removed lines struck through and added lines highlighted, with an "N added, M removed" summary; a new file shows its line count), so a stray test edit is seen before it reaches the branch.
- Per-route metadata: a manifest route may be written as `{ "file": "src/pages/about.html", "title": "About", "description": "…" }` instead of the bare page path (`pages` on the parsed manifest, `NativePageMeta`). The editor itself only uses the file; the exporter uses the title and description for the document head. There is no field for them in the editor UI yet.
- Static export (`shared/native-export.ts`, editor-owned, unit-tested in `tests/native-export.test.ts`): `exportNativeSite({ files, siteUrl })` is a pure function from repository files to output files, so it runs in Node and in the browser. It writes `<route>/index.html` per route with every custom element expanded into declarative shadow DOM that links the shared stylesheets and inlines the component's own stylesheet in the runtime's order, rewrites `#/route/` links to paths, marks the current nav link `aria-current="page"`, writes shared stylesheets and `src/images/` under `assets/` with content-hashed names (FNV-1a) plus `_headers` (HTML revalidated, assets immutable), adds image `width`/`height` from the file and `loading="lazy"` after the first section, and builds the head from the manifest's route title/description, else a leading `<!-- key: value -->` page comment, else the first `h1`/`p`, with site-wide values from `.astro-editor/site.json` (optional; without a URL the canonical and `og:url` tags are left out). `shared/native-export-cli.ts` is bundled by `npm run build:export` (part of `build:ui`) to `dist/native-export.mjs`, served at `https://editor.techies.tools/native-export.mjs`, so a site's deploy workflow fetches and runs it (`node native-export.mjs [dir] [--out dist] [--site-url …]`, `SITE_URL` also honoured) instead of keeping its own build script; `npm run export -- <dir>` runs it locally. ## Architecture

1. **Editor hosting:** Cloudflare Pages serves `dist` and Pages Functions delegate `/api/*`, `/auth/*`, and `/mcp` to the existing `worker/app.ts` handler. Pages cannot own a Durable Object class, so `native-site-editor-sessions` is a separate Worker owning the SQLite `SessionStore`; Pages binds to it by `script_name`.
2. **Unpublished preview:** source files and browser drafts render instantly inside the editor. Editing does not wait for GitHub, build jobs, or deployments.
3. **User website publishing:** later exporter should generate standalone site files and let each user own a separate Git-backed Pages project. Save-to-GitHub and website deployment remain separate operations.

Relevant limits checked 2026-09-23: Pages Free has 500 builds/month, one concurrent build, 20,000 files/site, 25 MiB/file, and 100 projects/account; Pages Functions share Workers Free request limits; SQLite Durable Objects are available on Workers Free with quota limits; GitHub App user tokens are bounded by both user access and App permissions; GitHub authenticated REST is normally 5,000 requests/hour. Pages Git integration can deploy pushed branches; Direct Upload projects cannot later switch to Git integration, so choose the production project type deliberately. No paid services were enabled.

Sources: [Pages limits](https://developers.cloudflare.com/pages/platform/limits/), [Pages Functions pricing](https://developers.cloudflare.com/pages/functions/pricing/), [Pages bindings and Durable Objects](https://developers.cloudflare.com/pages/functions/bindings/#durable-objects), [Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/), [GitHub App user tokens](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app), [GitHub REST rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api), [Pages Git integration](https://developers.cloudflare.com/pages/configuration/git-integration/), [Pages Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/).
