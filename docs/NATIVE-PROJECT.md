## Current Slice

Working:

- Browser-native preview for `.astro-editor/native.json`: persistent sandboxed iframe, HTML/CSS/component patching, shared styles, native slots, nested shadow DOM components, route-preserving source updates, and no Astro build per edit.
- Native preview click-to-select: a plain click on any preview element selects it immediately and opens the owning page/component source plus rendered matching CSS rules from the current document or shadow tree without reloading the frame. The owning file opens with the caret just after the element's start tag, which stays highlighted while the file is edited; the runtime reports element-child indexes and `src/native-source-location.ts` maps them to source offsets through the same browser parser. There is no mode button. Ctrl/⌘+click follows a `#route` link; the runtime's `route` message is read before the stale-render filter in `src/components/native-preview.ts`, as are the other messages that carry a user's action (`text-edit`, `format`, `move`, a `section-drag` cancel), so a click or key that lands while a render requested since is still pending (component styles arriving after the first paint) is acted on rather than dropped; the host checks each against the current source. Messages that describe the runtime's DOM (`select`, `text-selection`, `insert-points`, `structure`, the rects, a drag's start and target) stay filtered and are reported again after the render; a stale drag end, and the cancel the runtime sends when a render replaces the page under a drag, end the drag with "Section drag cancelled" instead of being dropped silently. The preview has no toolbar; the frame fills the pane above the code split.
- Edit bar: selecting an element in the native preview shows a contextual toolbar (`src/components/edit-bar.ts`) anchored to it inside the preview pane: 8 px above the selection when that fits, below it otherwise, else pinned to the frame top; it follows scroll and resize through `selection-rect` messages from the runtime and hides while the element is out of view or another file opens over the page. It does not appear for the page's `main` container. It starts with a kind label (Heading, Paragraph, Link, Section, or the tag for components), then: **Heading level** (H1–H6, renames both tags), **Text size** (not for `section`, `header`, `footer`, `nav`, `article`, `aside` or components; Default, XS–4XL as an inline `font-size` in rem on the element's start tag; an unlisted inline size shows as Custom; Default removes the declaration and an emptied `style` attribute), **B** and **I** (with text selected inside the element, wrap exactly that range in `<strong>`/`<em>`, or remove the enclosing `strong`/`em` (`b`/`i` too) when the selection already sits in one; with no text selected, the element's whole content is wrapped or unwrapped; Ctrl/⌘+B and Ctrl/⌘+I work inside the preview and with focus in the bar). The runtime reports the selection as offsets into the element's text content plus its enclosing inline wrappers; `textRangeInSource` maps those offsets to inner-source offsets, skipping tags and comments and decoding entities, verifies the decoded slice equals the selected text, and refuses a span that cuts through a tag (the bar then says to select text within one element). After the edit the runtime re-selects the same text so a second format applies to the same word. After B and I comes **Link** (the link icon, named Link, title "Link (Ctrl+K)"), shown only with text selected inside a text element that is not itself in a link, and **Remove link** (an unlink icon) with the selection or caret inside a link in a text element; both are described under Link address. Ctrl/⌘+K does what Link does, in the preview and in the bar. Then **Follow link** (for `#route` links, also when the selection sits inside one). Element ranges come from `locateNativeElementRange` in `src/native-source-location.ts`, which resolves the exact outer range (end tag found before the next non-descendant start tag; same-name descendants counted) and fails closed on implied end tags or stray markup, in which case only Follow link remains. Each action is one verified range edit and one undo step through the existing visual history; Ctrl/⌘+Z and Ctrl+Y with focus on a bar button run the same document shortcut as the rest of the editor. The runtime remembers the selected element's index path before each render and re-selects that position when the element was replaced (renamed heading, undo), and the host can request another position through `selectNode` in the update payload. The runtime reconciler pairs keyed nodes in order, so two elements sharing a `data-key` render as separate nodes.

The geometry stays in the runtime only: the gap from the siblings' midpoints (the same gap indexes as `insert-points`), and autoscroll while the pointer is within `min(72px, frame height / 4)` of the top or bottom edge, proportionally and at most 14 px per animation frame (also when the pointer is outside the frame), recomputing the gap after each real scroll. While dragging, the section is 55% opaque (its inline opacity restored afterwards), the plus buttons make way for every gap of its parent as a line, the one under the pointer a 44 px dashed band that reads "Drop section here"; the edit bar stays where it was (it does not follow the scrolled section, so the grip keeps its capture), its other controls are `inert`, and a re-render asked for meanwhile waits for the drag's end. A release on a changed gap goes through `moveNativeSectionTo` (one undo step, "Section moved", the section stays selected and its row marked); the gap it already fills announces "Section stayed in place" with nothing recorded; Escape, `pointercancel`, lost capture, a release outside the frame, or a render under the drag cleans everything up with no change and announces "Section drag cancelled". The grip is also a keyboard move handle: with focus on it, plain Up/Down move the section one place, as Alt+Up/Down do anywhere in the bar, and focus stays on it. The old start (a press on the selected section's own background inside the frame, with its pointer capture and swallowed click) is gone: a press and move inside the page only selects as usual.

## Architecture

1. **Editor hosting:** Cloudflare Pages serves `dist` and Pages Functions delegate `/api/*`, `/auth/*`, and `/mcp` to the existing `worker/app.ts` handler. Pages cannot own a Durable Object class, so `native-site-editor-sessions` is a separate Worker owning the SQLite `SessionStore`; Pages binds to it by `script_name`.
2. **Unpublished preview:** source files and browser drafts render instantly inside the editor. Editing does not wait for GitHub, build jobs, or deployments.
3. **User website publishing:** later exporter should generate standalone site files and let each user own a separate Git-backed Pages project. Save-to-GitHub and website deployment remain separate operations.

Relevant limits checked 2026-09-23: Pages Free has 500 builds/month, one concurrent build, 20,000 files/site, 25 MiB/file, and 100 projects/account; Pages Functions share Workers Free request limits; SQLite Durable Objects are available on Workers Free with quota limits; GitHub App user tokens are bounded by both user access and App permissions; GitHub authenticated REST is normally 5,000 requests/hour. Pages Git integration can deploy pushed branches; Direct Upload projects cannot later switch to Git integration, so choose the production project type deliberately. No paid services were enabled.

Sources: [Pages limits](https://developers.cloudflare.com/pages/platform/limits/), [Pages Functions pricing](https://developers.cloudflare.com/pages/functions/pricing/), [Pages bindings and Durable Objects](https://developers.cloudflare.com/pages/functions/bindings/#durable-objects), [Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/), [GitHub App user tokens](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app), [GitHub REST rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api), [Pages Git integration](https://developers.cloudflare.com/pages/configuration/git-integration/), [Pages Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/).
